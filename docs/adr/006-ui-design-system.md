# ADR-006: UI デザインシステム

- ステータス: 採用
- 期間: 2026-08-21〜2026-08-25
- 元文書: goals/2026-08-24-v4-ui-redesign.md、goals/2026-08-24-mock-alignment.md、goals/2026-08-25-design-conformance.md、goals/2026-08-21-character-screen-v2.md(git 履歴参照)

## 背景

キャラ画面はユーザーの実使用フィードバック(入力方式が不統一、バフの効果が即座に見えない、調整値の意味が伝わらない)を機に v2 化し、「数値欄+スライダー+MAX の 1 部品に統一」「設定を触ると保存前でも最終能力値が即時更新」を確立した。この基盤の上に、旧サイドバー+3カラム構成をやめ、デザインモック「TW Toolkit Prototype v4」準拠の「上部タブ(ホーム/ダメージ計算/キャラ)+ 左キャラレール」へ全面刷新した。

刷新直後は骨格(タブ・レール・ホームの到達一覧・計算の3段構造)のみが実装済みで、中身の密度と規格化が残っていた。モック整合 goal で `TW Toolkit Redesign.dc.html`(方向性探索シート)と現状 UI の差分を埋めたが、Redesign は v4 が採らなかった探索方向も多く含むため、v4 を正としてどの案を採るかを都度判断した。

さらに、規格文書 docs/design-system.html は 2026-08-25 に新設したもので、**実装のほうが先に存在していた**。つまり適合していない箇所が必ずあり、1 周の監査で全部見つかる保証もないため、「監査→分類→修正→記録」を繰り返す適合ループ(design-conformance goal)を回した。ループは規格と実装のどちらが誤っているかを毎回判定する点が特徴で、機械的な一括修正はしない。

## 決定

- 画面構成は「上部タブ+左キャラレール」(v4)。旧サイドバー+3カラムの `pages/character`・`pages/damage` は削除し後方互換を保たない
- Redesign 規格シートからは **12a(装備の3ペインドリルダウン、最新)・3a(角丸・アイコン規格)・2a(コンポーネント規格)・5b(上限で捨てた分の可視化)・5c(攻撃/防御を同列タブに)** を採用。**4a/6a/6b/7a(かんたんモード・一式テンプレ・充足度メーター・精度メーター)は不採用**(12a のドリルダウンに置き換わる方向のため)
- 角丸を4段に固定: `--r-window` 12(窓・大カード)/ `--r-panel` 9(パネル・ボタン・フィールド・タブ)/ `--r-inset` 6(インセット面・表・小チップ)/ `--r-pill` 999(バッジ・チップ)。直書きは全廃(丸ドットの `50%` のみ例外)
- タイポは4つの役割トークン(`--t-result` 44 / `--t-heading` 19 / `--t-body` 12.5 / `--t-label` 10.5)を新設し、**実値が一致する箇所だけ**置き換える。カード見出し(11px)・小ラベル(9〜9.5px)は v4 の情報密度を保つため据え置き
- インセット面 `--surface-inset`(#C1D3E6、2a の窓3層目)を追加。白 = 編集できる面、インセット = 読み取り専用の区別を面で表現する
- ラベンダー(#6D6AA8)を `--sim` としてトークン化し、「保存されない・一時」専用に予約する。保存済みデータの表示に流用しない
- アイコンは4系統(キャラ/Mob/スキル/バフ)を枠色・角丸で識別し、サイズは20(行内・チップ)/28(一覧行)/40(選択カード)/64(キャラ詳細)の4段に固定。id は gamedata の値から機械的に解決し(手動マッピング表を作らない)、**解決できない id は破線+`?`**、**そもそも対象が無い id === null は縞のまま**で warn も出さない、という2状態を区別する。アイコン単独表示は禁止(名前併記が既定)
- 装備ペインは12aの密度に寄せる: アビリティは系統(`EquipmentAbilityFamily`)ごとの Select 4行(同系統重複は storage 検証でも拒否)/ エンチャントに上限ゲージ常設 / 基本とエンチャントを同じ行 / 装備合計を表に / 補正源の並びを「キャラステータス→装備→シエナ→テシスコア→神鳥の聖物→クラウン→スキル→モンスターカード→ペット」の指定順に固定 / パワーウェポン・ストロングウェポン Lv6(計+20%)を**新規登録キャラの既定 ON**にし変更は例外操作へ(既存キャラの値は書き換えない)
- 上限で捨てられた分は既存の `CategoryTrace` の `raw − value` で表現する(新しい持ち物を増やさない)。防御側パネル(防御力/カット率/回避)は与ダメージ式と別モジュール(`defense.rs`)にし、未実装項目は0で埋めず `Option::None` + 破線「未実装」で示す。攻撃/防御は同列タブ
- 小粒: スキルピッカーは対象への合計ダメージ降順 / 段数違いコンテンツは `ContentSeries`(id接頭辞+末尾数値で機械決定)で1行+ステッパーに畳む / バフは「常時(保存済み)・追加(試し変更のみ)・使わない」の3状態を**保存済みかどうかから導出**し、常時への昇格はチップのクリックではなく既存の「キャラに保存」操作に寄せる
- デザイン適合ループの終了条件は「①機械監査+実機監査が全画面で違反0」「②残る非適合が§14に決定待ちとして登録済み」「③2周連続で新規違反0」の同時達成。判定は毎回「違反(実装を直す)/規格の穴(規格を直す)/決定待ち(§14へ)」の3分類を経る。機械監査(`tools/design-audit/run.py`)は候補を出すだけで判定・自動修正はしない
- §00の15項目(いつでも意識する5つの具体化)が規格の重心で、§03/§04/§05 等の数値規格は結論に過ぎない。§08「部品」・§11/§12「組み上がり」は寸法まで書いた実物の節なので、新規部品も既存修正もまずここと突き合わせる
- §09規則2(ドリルダウンは置き換えず右にペインを増やす)に従い、装備・シエナのオーラの部位詳細は補正源/一覧/詳細の3ペインにした
- §10(動きと変化)は6つの型(数値の跳ね/バーの幅/ペイン出現/ポップオーバー/バッジ/開閉)+ `prefers-reduced-motion` として `app.css` に配線。同時に変わる値は全部動かす(§10規則2)
- 入力は5形態の上から試す: 順序のある有限選択は `StepSelect.svelte`(段階選択)、オン/オフはチップ。フィールドは「表示が既定・編集は例外」(初期値は常に埋まっているため、触るまでは読み取り表示)。範囲は値の隣に常設する
- §14「これから作る画面の決定」6件の要旨: ①ダメージは1発→合計→DPSの「鎖」で出す(1発=ゲート、DPS=レート) ②DPSに到達判定バッジは付けない ③効いていない分の棚卸しは「なぜこの数字?」内の1箇所に集約 ④補正源リストはお気に入り+ドラッグ&ドロップで並べる(操作頻度の固定3群案は不採用) ⑤相手依存の値はキャラ側(供給源)と計算タブ側(相手への効き)に分ける(先例: 属性・クリティカル率) ⑥試し変更は同時3件まで(上限到達は色でなく文言で伝える)

## 却下した選択肢

- Redesign の 4a/6a/6b/7a(かんたんモード・一式テンプレ・充足度・精度メーター) — 12a のドリルダウンに置き換わる方向なので不採用
- 規格シート 3a の 16px 角丸系列 — 「親しみを増す」ための探索方向で、v4 系列(12/9/6/pill)を保つため不採用
- リサイズ可能ペインライブラリ(`paneforge` 等) — px 単位の最小幅・ネストした状態受け渡しの要件を満たさず自作 `Splitter.svelte` にした
- `CategoryTotals` に「捨てた量」を新しいフィールドとして持たせる案 — 既存の `raw`/`value` の差分で表現でき二重管理になるため不要
- 補正源リストを操作頻度で3群に固定 — 「どれをよく触るかは人による」「▲▼は並べ替え操作として最悪」という指摘でお気に入り+ドラッグへ変更
- バフの3状態をクリック巡回で切り替える実装 — `追加→常時` は保存を伴うため巡回に混ぜず、バッジ表示+既存の保存操作に寄せた
- 機械監査候補の一括置換・CI組み込み — 違反か規格の穴かは判断が要るため、候補提示どまりにして人が分類する

## 経緯

- タイポトークンは当初4段への完全置換を検討したが、カード見出し(11px)・小ラベル(9〜9.5px)まで寄せると3タブで情報量が減るため、**役割の名前を与えるところまで**に留めた(ユーザー決定)
- 装備の部位詳細ドリルダウンは1周目で「視覚回帰の切り分けができない」として見送り、2周目で3ペイン化を単独実施した
- 適合ループの終了条件3(2周連続0)は10・11周目で一度達成したが、12周目に §09規則1違反(バフを押すと位置が変わる)が出て仕切り直した。原因は監査が「押すと開くもの」しか列挙しておらず「押すと状態が変わるもの」を網羅していなかったこと
- 監査手法は14周目に「手書きチェックリスト」から「画面から自動列挙する」方式(`sweep.js`/`inputs.js`/`surfaces.js`/`bands.js`/`motion.js`)へ書き換えた。手書きリストに無いものは永久に見つからないと分かったため(シエナのオーラの見落としが実例)
- 18周目、シエナのオーラは「段階を入力させる」設計から「能力値スロットを1個ずつ選んで積む」設計へ作り直した(ユーザー決定: 補正値は加算式なので段階入力は不要)。以降、武器アビリティ・エンチャント表示も同様に、プルダウン/固定ボタン式から**チップを押すと行が積み上がる**形へ複数周かけて収束した
- 上限到達の面色は「金か紫か」で規格内が食い違い(保留C)、20周目に「通常バーは青・上限到達は金、入力面は白のまま(ラベンダーは保存されないにのみ使う)」で確定した
