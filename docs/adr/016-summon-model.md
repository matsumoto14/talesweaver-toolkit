# ADR-016: 召喚獣のモデル(アナイスの魔法人形)

- ステータス: 採用
- 期間: 2026-09-17 〜

## 背景

- アナイスの火力は、魔法人形(ミカベア / ルシベア)が自動で撃つスキルと本体のスキルの**合計**。人形の攻撃力は STAB 依存・物理判定のまま、中身が INT と魔法攻撃力から来る(wiki Skill/アナイス「魔法人形の仕様」: STAB/突き攻撃力 = アナイスの INT/魔法攻撃力、HACK/斬り攻撃力 = HACK/基本斬り + 強化魔防、INT = 1)。
- ツールは「攻撃者は本体 1 人」を前提にしていた。人形のスキル 8 件は `SkillDependency::Stab` で登録されており、本体の突き係数で計算されていた(INT を上げても動かず、エンチャント案内が突きを指す)。DPS も片方ぶんしか出なかった。
- wiki「計算式まとめ」の依存表には **`STAB(熊)` という行が最初からある**(ステ係数 INT 2.1 / HACK 1.08、装備係数 基本/強化 = 斬り 3.75/0・魔攻 23.75/32.5・魔防 0/18.75、命中P補正 INT×0.1 − INT/100)。STAB の行の STAB を INT に、突きを魔攻に置き換えた形で、キャラページの記述と一致する。
- 同じ表の上にあった「召喚獣は各装備補正の下限を 1 として計算する」は取り消し線付きで「この機能は削除」。
- wiki 自身が「召喚による仕様」「魔法人形の仕様」を「2026/4/1 アップデート以前の情報なため要再確認」と断っている。

## 決定

1. **攻撃者(`Attacker`)を語彙として立てる。** 値は `Player` / `MagicDoll` の 2 つで始める。スキルは「誰が撃つか」を持ち、値は `gamedata` の副表(スキル id → 攻撃者。`ACTUAL_DELAYS` と同型)から付ける。`s(...)` の引数は増やさない。
2. **`SkillDependency` に variant を足さない。** 物理 / 魔法判定・武器系統・装備条件・ランダム OP の「STAB 依存ダメージ増加」は STAB のまま(wiki に「熊は物理攻撃」と直接書かれている)。変わるのは攻撃力と命中P の**係数の実体だけ**なので、判定用途の 11 か所の網羅 match に「熊とは何か」を教える必要が無い。
3. **係数は wiki の `STAB(熊)` 行をそのまま持ち、「攻撃者 + 依存 → 係数」を返す 1 関数から引く。** commands 側にあった 2 つのラッパーと `gamedata::equipment_coefficients` の直呼びを全部その関数に寄せる。1 経路でも取りこぼすと、その経路だけ熊が本体の突き係数で計算されて静かに間違うため。起動時のグローバル表(キャラ文脈を持たない)だけは本体固定のまま。
4. **装備補正の下限 1 は実装しない**(wiki で削除済み)。
5. **合成は `calculate_damage` の外側で行う。** 同じ能力値・装備・バフを 2 回通し、熊側は係数だけ差し替え・`combo_count = 0`。合計 DPS = 本体 + 熊の単純和(本体は召喚中も手が止まらない。プレイヤーの実戦から)。討伐時間は合計から出し直す。
6. **熊の攻撃間隔は `基本中ディレイ × (1 − 中ディレイ減少値) + 0.0705s`。** 実測回数表は本体プレイヤーの実測なので熊には使わない。減少値は本体用に求めた値を流用する(wiki は減少値 0% と 35% の両方で式の一致を確認している)。コンボ中の ×0.5 は掛からない。
7. **キャラに「熊が撃つスキル」を 1 つ保存する**(`summon_skill_id`、SQLite v16 / IndexedDB v6)。自動化するスキルは 1 つを前提にする(wiki は複数自動化を書いているが、運用は 1 つ)。未選択なら熊の鎖は出ない(0 で埋めない)。
8. **主軸スキルは攻撃者ごとに 1 本。** 候補は攻撃者で絞り、検証も「そのキャラのスキルか」に「攻撃者が合っているか」を足す(書き出し / 読み込みや手編集で熊のスキルが本体の主軸に入る経路を塞ぐ)。エンチャント案内は両攻撃者の装備係数の非ゼロ成分の和集合。
9. **ホームは人形スキルを本体評価から除外し、同じ変更で熊ぶんの期待 DPS を毎コンテンツ足してから討伐時間を出し直す。** 除外だけで止めると「熊を無視した評価」が完成として残る。
10. **専用の面は作らない。** 計算タブは鎖を攻撃者ごとに 1 本並べ、その下に合計 DPS と討伐時間を ReadRow の面(インセット + ラベル + 固定幅の値。本文の大きさ)で付ける — 2 本の鎖は同じ寸法・同じ列位置で描く(本体だけ 44px にしない。ユーザー判断 2026-09-18 — 答えは合計面と「行ける?」帯が持つ)。鎖のバッジには撃つ人の絵(本体 = キャラ、熊 = 召喚スキル「ミカベア召喚 / ルシベア召喚」のアイコン。ルシベア専用スキル(`anais_rucy_*`)だけルシベア、両方の人形が撃つ 4 件はどちらか保存していないのでミカベアの絵で代表させる)を置く。「なぜこの数字?」は面を増やさず、見出しの 本体 / 熊 の 2 択か最後に節を押した鎖で攻撃者を切り替える(攻撃者ごとに開閉・変わった行の控えを分けて持つ)。「いまの実力」帯は 熊 / 本体 のチップで切り替える(保存しない)。ホームの見た目は全キャラ共通のまま、判定に使う値だけ合計にする。
11. **今回は魔法人形だけ。破壊精霊は入れない。** 精霊のステータスの式は wiki に無く、「本体のステをそのまま使う」は推測でしかない。精霊のスキル(区分 アンC / アンS など)は本体扱いのまま残す(既知の近似)。精霊を足すときは `Attacker` に 3 つめの値を増やす。「召喚獣」という 1 つの値でまとめない(人形と精霊で係数も間隔の根拠も違う)。
12. **召喚枠は 1 つ。** 人形と精霊の同時は無い(プレイヤーの実戦から)。だから熊の鎖の隣に並ぶ本体スキルは QA・C 区分に限られ、破壊精霊のスキル(チェーンライトニング等)は並ばない。守護精霊は殴らない(攻撃スキル 2 件はどちらも本体の QA)。

## 理由

- 係数の 1 行を差し替えるだけで済むのは、wiki が `STAB(熊)` を依存の 1 行として書いているから。自前で「熊のステータス」を組み立て直すと、次に wiki が変わったとき追えなくなる。
- `SkillDependency` に足す案は、既存 19 キャラの共通コード(判定・武器系統・装備条件)に「熊にとって無意味な分岐」を書く判断ミスが紛れ込む。別軸にすれば既存キャラの計算結果に影響しない。
- 面を 2 種類に割ると、以降の変更を両方に入れ続けることになる。鎖(1 発 → 合計 → DPS → 討伐時間)を残せば「なぜこの数字?」の掘り下げ先も残る。

## wiki も分かっていないこと(埋めずに出す)

計算式まとめの召喚獣適用可否は熊の列がほとんど `?`。クリ率増加・命中P増加・ペット集中・テシスコア・ソウルリンク・装備強化・カテゴリ倍率・防御力無視・熊の属性値の出どころは未検証。「STAB 依存ダメージ増加」は AF のバフだと二重に乗るという注記があり、ランダム OP を入れるときに分ける。中ディレイ減少値は「召喚時点の値を維持する模様(要検証)」とあるが追わない。0 や「効く」で埋めず、分かっていないものとして扱う。

## 突き合わせ(必須)

wiki の人形仕様は 2026/4/1 以前の情報と断られているので、ゲーム内の実測と合わせるまでは完成扱いにしない。合わなければ係数の行のほうを疑う。

手順(2026-09-18 に画面を用意):

- **実測タブ**でスキルに熊のスキル(極・熊連など。候補の注記に「熊」と付く)を選び、ゲーム内の表記ダメージを記録する。計算値は選んだスキルの攻撃者(`Skill::attacker`)から係数を引くので、熊のスキルを選べばそのまま熊の 1 発になる(本体の枠 `body` に入る。熊の鎖 `summon` は見ない)。送る本文と JSON(`version: 4`、`skill.attacker`)に「熊」と入る。
- **計算タブ**の「なぜこの数字?」は最後に節を押した鎖に付いてくる。見出しの「熊」を押す(または熊の鎖の節を押す)と、① 攻撃力をつくる → ステ攻撃力 / 装備攻撃力 の掘り下げの先頭に「係数 STAB(熊)」の行(INT 2.1 / HACK 1.08、装備 斬り 3.75/0・魔攻 23.75/32.5・魔防 0/18.75)が 1 行増える。値はトレース(Rust)から出すので、`gamedata` の係数を直せばここも変わる。
- 合わないときは `crates/gamedata/src/characters.rs` の `MAGIC_DOLL_ATTACK_COEFFICIENTS` / `MAGIC_DOLL_EQUIPMENT_COEFFICIENTS` を疑う。敵側(防御力・カット率)は本体のスキルで別に確かめてからでないと切り分けられない。

## 追記(2026-09-18): 破壊精霊を入れる

決定 11「今回は魔法人形だけ。破壊精霊は入れない」を、同項が予定していた「`Attacker` に 3 つめの値を増やす」形で解除する。

11'. **`Attacker` に `DestructionSpirit`(破壊精霊。アンフェル / グレシス / イグニー)を足す。**「召喚獣」という 1 つの値でまとめない方針は変わらない(決定 11 の理由のまま)。ただし精霊は熊と違い、**wiki 計算式まとめの依存表に専用行が無い**(あるのは `STAB(熊)` だけ)。精霊のスキルは全件 INT 依存・魔法で、キャラページにも本体と別の係数を示す記述が無いため、`attack_coefficients_for` / `equipment_coefficients_for` / `accuracy_correction_for` は `Player` と同じ `dependency` の行(INT)へそのまま委譲する(熊のような固定係数テーブルは持たない)。精霊が撃つスキルは 8 件(電撃攻撃・チェーンライトニング・結晶攻撃・クリスタルスプリンター・リングオブアイス・火炎攻撃・ファイアブラスト・ディトネート)。**陣の 3 件(テスラコイル・アイスエイジ・フレアフィールド)と守護精霊のスキルは本体扱いのまま**(wiki スキル性能一覧に「陣による攻撃はアナイス本体がダメージを与えた扱いになる」と明記)。合成(決定 5)・攻撃間隔(決定 6)・召喚枠 1 つ(決定 12)は熊と同じ経路をそのまま通す(2 系統に分けない)。

11''. **主軸スキルが召喚獣の型を決め、召喚欄はその型の候補に絞って自動で差し替える。** 主軸のうちベアステップ(`anais_mica_bear_step` / `anais_rucy_bear_step`)と陣(`anais_tesla_coil` / `anais_ice_age` / `anais_flare_field`)は wiki の型分け通りそれぞれミカベア / ルシベア / アンフェル / グレシス / イグニーの型を持ち(`Skill::summon_form`。共通スキル・守護精霊は型を決めず `None`)、召喚スキル 16 件も自分が属する型を持つ。主軸を変えたとき、保存済みの召喚スキルが新しい型の候補に無ければ、その型で**継続火力(`power_per_second`)が最大**のスキルへ差し替える。候補の並びは主軸と同じ「単体優先 → 継続火力順」(`main_skill_order`)のままだが、自動で入れる 1 件は並びの先頭にしない — 召喚獣は自分で撃ち続けるので単体 / 範囲の区別より DPS が効き、先頭を採るとミカベアで †極・突き(単体の基本攻撃)が入って熊連より弱い既定になる(実機確認 2026-09-18)。候補に入っていれば(同じ型のまま)手で選んだものを尊重して触らない(ux-guidelines「入力欄は自動値を上書きする例外操作」。ユーザー判断 2026-09-18)。対応表は `gamedata`(`SUMMON_FORMS`)だけが持ち、TS には書き写さない — フロントは `Skill.summon_form` を読むだけ。

バフ適用可否(wiki には「精霊」列があり、クリ率増加バフ・極のルーン・射手のルーン・命中率増加バフ・ハードウエポン・手袋ランダム OP が × と記載)は今回実装しない(熊と同じ「未検証のまま計算に入れる」扱いにする。ユーザー判断 2026-09-18)。wiki が分かっている限りの一覧をここに残すだけで、コードには反映しない。

計算タブの鎖・バッジ・見出しの 熊 / 精霊 表記、アイコン(アニメ 95596 の 34/35/36 番 = テクスチャ 13322 のコマ 65/67/69、雷 = アンフェル・水 = グレシス・火 = イグニー)の出どころは `apps/desktop/src/assets/icons/README.md` を参照。

破壊精霊を足す前は召喚スキル(熊のスキルも含む)が本体の主軸に選べてしまっていたため、既存キャラの
`main_skill_id` がそれを指しているとキャラタブの自動保存が検証エラーで止まる。主軸に入っていた
召喚スキルは召喚欄へ移す保存データ移行(SQLite v17 / IndexedDB v7)を足した。詳細は docs/adr/008-storage.md。
