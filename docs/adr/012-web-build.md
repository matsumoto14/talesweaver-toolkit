# ADR-012: デスクトップとブラウザの両対応

- ステータス: 採用
- 期間: 2026-08-31
- 関連: [008 storage と migration 方針](008-storage.md)、[009 一般公開・配布](009-public-release.md)

## 背景

配布物は Windows のインストーラだけで、試すには署名のない実行ファイルを落として入れてもらう必要があった。
「まず触ってみたい」人にとってこの段は高く、リンクを開けば動くブラウザ版があれば入口として弱くない。

土台は既にあった。`domain` の依存は `serde` + `thiserror`、`gamedata` は `serde` + `domain` だけで、
OS にも DB にも触っていない(ADR-008 で「静的データを storage に入れない」と決めた分離がここで効いた)。
CI も 2026-08-31 から `cargo check --target wasm32-unknown-unknown` で wasm ビルドを守っていた。

残っていたのは 2 つ。**計算がコマンド層(`src-tauri`)に混ざっていた**こと(薄いアダプタのはずが、
44 コマンドのうち保存に触らないものまで Tauri の中にあった)と、**保存が `rusqlite`** で
wasm では動かないことである。

## 決定

- **画面とコマンド呼び出しの境界を `api/commands.ts` 1 枚に保ち、実体をビルドで差し替える**。
  画面は 44 コマンドすべてをこのファイル経由で呼び、その先の `api/invoke.ts` を
  `vite.web.config.ts` の alias でブラウザ版だけ `invoke.wasm.ts` に切り替える。
  **実行時にプラットフォームを見て分岐しない**のは、デスクトップ版のバンドルに WASM を
  積みたくないため(1.3MB。使わないコードを配って初回起動を遅くする理由がない)。
  画面側に `if (isBrowser)` を 1 つも書かないため、Tauri プラグイン(外部リンク・HTTP・更新・
  プロセス)も同じく alias で `src/web/*.ts` の実体に差し替える
- **計算は共通 crate に置く**。保存に触らないコマンドの中身を `crates/commands` へ移し、
  デスクトップ版(`src-tauri`)とブラウザ版(`crates/web`)の両方がそこを呼ぶ。
  計算が 2 つに分かれると、片方だけ直った状態に誰も気づけない
- **ブラウザ版の入口は `invoke(command, args)` の 1 本だけ**にする(`crates/web`)。形を Tauri に
  揃えておけば、画面はコマンドごとのバインディングを持たずに済む。引数は camelCase の
  JS オブジェクトで来るので、コマンドごとの引数 struct(`#[serde(rename_all = "camelCase")]`)で受ける
- **保存は共通化しない**。44 コマンドのうち 26 は WASM が `commands` を呼んで返し、
  残る 18(キャラ・バフセット・アイコン・実測スナップショット・登録済みキャラでの計算・
  アプリ情報)は TS 側で IndexedDB(`api/browserStore.ts`)が受ける。保存の前検証だけは
  `domain` を持つ WASM に問い、エラー文言をデスクトップ版と揃える
- **書き出し / 読み込み(JSON)を必須機能として付ける**。ブラウザの保存領域はサイトデータ削除で
  黙って消え、端末間でも行き来しない。消えるものを預かるなら、持ち出す手段を同時に出す
- **番人を CI に置く**(2026-08-31)。ブラウザ版は普段の開発で触らないので、放っておくと
  デスクトップ版だけが進んで静かに壊れる。`cargo check --target wasm32-unknown-unknown` を
  `commands` / `web` まで広げ、`npm run build:web` を通し、画面から `@tauri-apps/` を
  直接 import していないかを見る。加えて、画面が渡す引数名と Rust の引数 struct の
  フィールド名を突き合わせるテスト(`crates/web/src/args_check.rs`)を足した

- **配信は GitHub Actions でビルドして Cloudflare Pages(`app.tw-context.dev`)へ成果物だけ送る**。
  紹介ページ(`tw-context.dev`)とは**別プロジェクト**にして、ページの更新でアプリを落とさない
  (問い合わせ中継を別プロジェクトにしたのと同じ理由)。Pages の Git 接続にしないのは、
  ビルドに Rust と wasm-pack が要るため — Pages のビルド環境に載せると壊れやすい。
  手順は docs/web-deploy.md

## 却下した選択肢

- **Rust 側に保存の trait を切って両対応にする**: `crates/storage` を `trait Store` にし、
  wasm では IndexedDB 実装を挿す案。IndexedDB は非同期なので、WASM から JS の Promise を
  待つ(`wasm-bindgen-futures`)ことになり、`commands` 全体を async に染めるか
  ブロッキングの偽装が要る。得られるのは「保存のコードが 1 つ」だけで、実体は
  SQLite と IndexedDB の 2 本のまま。TS 側に 200 行ほど書く方が安く、境界も素直だった
- **実行時にプラットフォームを見て分岐する**(`window.__TAURI__` の有無): 分岐が画面側に散り、
  「ブラウザ版で試していない画面」が増えるほど壊れる。1 つのバンドルにデスクトップ版でも
  ブラウザ版でも使わないコードが両方入る。alias なら境界は `vite.web.config.ts` の
  数行に収まり、CI の grep で守れる
- **OPFS 上の SQLite(sql.js / wa-sqlite)で `crates/storage` をそのまま動かす**: 保存のコードは
  1 つになるが、SQLite の wasm ビルド(数百 KB)と OPFS の同期アクセスハンドル(Safari の
  対応状況・ワーカー必須)を抱え込む。**現在の要件は「ブラウザで試せること」**であって
  「ブラウザで SQL を実行すること」ではない(AGENTS.md「現在の要件を満たす最もシンプルな実装」)
- **ブラウザ版は保存なし(計算だけ)で出す**: 最初はこの形で始めたが、キャラを登録できないと
  ダメージ計算そのものが試せず、入口として機能しないことがすぐ分かった
- **データをサーバーに預けて端末間で同期する**: 匿名で使えるという性質(ADR-009)を捨てることになり、
  預かる先の運用も抱える。書き出し / 読み込みで足りる

## 対象外

- デスクトップ版とブラウザ版のデータ同期(意図的に行き来させない)
- ブラウザ版での自動更新・DB バックアップ(どちらもデスクトップ版だけの仕組み)
- ブラウザ版の中でしか起きない不具合の検証(いまは実機確認 1 回ぶんしかない)

## 経緯

- 2026-08-31 `NewCharacter` を storage から domain へ移し、保存に触らないコマンドの中身を
  `crates/commands` へ切り出した(Tauri のコマンドはアダプタに戻った)。
- 2026-08-31 `crates/web` で `invoke` を公開 → 画面の呼び出しを alias で切替 → IndexedDB の
  保存層 → 保存が要るコマンドを接続 → Tauri プラグインの差し替えと書き出し / 読み込み、の順に積んだ。
- 2026-08-31 CI に wasm ビルド・ブラウザ版ビルド・境界の grep・引数名の突き合わせを追加。
