# ADR-001: ドメインモデルと構造ファースト

- ステータス: 採用
- 期間: 2026-08-21
- 元文書: goals/2026-08-21-minimal-e2e.md、goals/2026-08-21-character-stat-sources.md(git 履歴参照)

## 背景

最初の動くスライス(キャラ登録 → ダメージ計算)を作るにあたり、ダメージ計算を先に実装する「計算ファースト」ではなく、ゲームのドメインモデル(キャラステータス・ダメージカテゴリ)の構造を先に立てる方針を取った。続く「キャラステータス補正源」goal では、キャラの実効ステータスを構成する補正源(ペット S スキル・ルーンスキル・クラウン・神鳥の聖物・常用バフ・調整値)をドメインモデルとして追加した。

## 決定

- **素ステ(振り分け分)の上限は各 310**(wiki 未記載、レベル上限 310 に一致する実測値として採用)。最終能力値の上限はエタの意志で 2400(出典: エタの意志ページ Lv100「最大ステータス開放」2,400)
- **キャラステータス(STAB/HACK/INT/DEF/MR/DEX/AGI の 7 種)と装備値(突き/斬り/魔攻/物防/魔防/命中/回避/敏捷/クリ)は計算上別系統**。両者を同一モデルに混在させない
- **ペット/ルーン/クラウン/聖物などの恒常補正はすべて素ステ 310 の外側、最終能力値側のレイヤーに属する**。素ステの値域チェックとは独立に扱う
- **能力値計算は 5 レイヤー(割合増加(素ステ比)/固定値/倍率A/倍率B/最終固定値)を `StatModifiers` として先に器を作る**。未実装の間は全レイヤー中立値とし、バフ導入時にレイヤー構造自体は変更しない
- **ダメージカテゴリは wiki の全カテゴリ(A〜Y、New1/New2、V1/V2、E1/E2 ほか)を単一 enum `DamageCategory` で最初から全件定義**し、`CategoryKind`(代入/固定値/割合)とキャップを列挙する。未使用カテゴリも中立値(割合=1.0、固定値=0)で式に参加させ、後から式へカテゴリを継ぎ足さない
- **同一カテゴリ内のキャップは加算後の合計値(Σ)に対して適用する**(値を足すたびに都度キャップするのではない)。加算順序に依存させない
- **丸め処理は専用関数(floor/2位切捨)にまとめ、式のコードに裸の丸めを書かない**
- **ペット S スキル・ルーンスキル・クラウン・神鳥の聖物は gamedata の「表」ではなく、domain の型(`PetSkillTier`/`RuneLevels`/`Crown`/`SacredRelic`)がステごとの段階→値の変換をメソッドとして持つ**。カタログ的な複数エントリの一覧ではなく「ステごとに1段階/Lv/数値を選ぶだけ」の構造だから
- **常用バフは個別にコードで if 分岐せず、`BuffDefinition`(id/対象/レイヤー/値/排他枠)のデータで解決する**。`build_modifiers` はカタログを線形探索するだけの汎用関数とし、バフ追加はカタログにデータを1件足すだけにする
- **値域の検証(`BaseStats::validate()`、`StatSources::validate()`)は domain 側に実装し、storage 側はそれを呼ぶだけにする**。値域はゲーム仕様(ドメイン規則)であり storage 固有の制約ではないため
- **gamedata は当面 JSON ではなく Rust のリテラル(const/関数)で持つ**。シードが十数件の間はローダとスキーマ検証を作るより型で持つ方が単純で、スクレイパー導入時に JSON + ローダへ移す

## 却下した選択肢

- ペット/ルーン/クラウン/聖物を gamedata のカタログ(表)として持つ: 却下。「ステごとに1段階を選ぶだけ」の構造はバフのような複数選択項目の集合と異なり、型のメソッドの方が単純
- 常用バフを個別コードで if 分岐して実装: 却下。CLAUDE.md の原則に反し、新規バフ追加のたびにコード変更が必要になる
- gamedata を最初から JSON + ローダで持つ: 却下。現状の十数件のシード規模ではローダ/スキーマ検証のコストが見合わない

## 経緯

- 最小 E2E の時点では能力値の上限を暫定 1500/2000 としていたが、キャラステータス補正源 goal で素ステ上限 310・最終能力値上限 2400(エタの意志)に修正され、こちらが現行値
- 最小 E2E で「全レイヤー中立値」だった `StatModifiers` は、キャラステータス補正源 goal で `StatSources → StatModifierSet` の純関数(`build_modifiers`)により実データから自動構築される形に拡張された
- カテゴリ A(攻撃力)の内訳は当初 旧リポ係数からの暫定値で導入されたが、後続の装備攻撃力に関する決定で置き換えられている(詳細は該当 ADR を参照)
