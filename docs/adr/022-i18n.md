# ADR-022: 表示言語(日本語 / 韓国語)

- ステータス: 採用
- 期間: 2026-09-24 〜
- 関連: ADR-012(ブラウザ版)、ADR-020(wiki に聞く)

## 背景

韓国のプレイヤーにも使ってもらうため、画面の文言とゲームデータ名(スキル・装備・バフ・敵・称号など)を
韓国語で出せるようにする(ユーザー判断 2026-09-24、デスクトップ版・ブラウザ版の両方)。
着手時点で文言はすべて日本語の直書きで、`t()` の外の日本語は画面側だけで約 2 万字(コメント除く)。
Rust もトレースの出どころ(「フルスロットル」)・部位名・エラー文を日本語で組み立てて返し、
画面はそれをそのまま出している。バフタブはトレースの出どころとバフ名を**文字列で**突き合わせている。

## 決定

1. **鍵は日本語の文言そのもの(gettext 方式)**。画面は `t("閉じる")` と書き、`apps/desktop/src/i18n/ko/*.json`
   (日本語 → 韓国語)を引く。辞書に無ければ日本語のまま出る。理由:
   - 日本語が正で、開発者も日本語で読む。`t("about.title")` のような鍵を挟むと画面のソースが読めなくなる
   - Rust が返す固定の表示名(部位名・出どころ名)も**同じ `t()` に通すだけ**で訳せる。Rust に言語を
     持ち込まず、突き合わせは日本語の元の文字列のまま行えるので、バフタブの文字列突き合わせも壊れない
   - 訳の漏れ・古い訳・`{name}` の穴の食い違いは `tools/i18n/check.py` が数える(型では守らない)
2. **言語はページを読み込むたびに 1 回だけ決まり、切り替えは読み込み直し**。labels.ts のように
   モジュール評価時に文言を作る所がそのまま効き、画面に言語の変化を追う仕掛けが要らない。
   切り替えは情報パネルの段(押した瞬間に読み込み直す)。選んだ言語は localStorage(`tw-locale`)。
   選んだことがなければ `navigator.language` が韓国語のときだけ韓国語
3. **辞書は出どころでファイルを分ける**。`ui.json`(画面の文言、Claude が訳して Codex がレビュー)・
   `terms.json`(画面が持つゲーム用語。韓国側の資料で裏取りする)・`rust.json`(Rust が返す表示名と文。
   使用は点検スクリプトが Rust のソースから数える)・`names.json`(ゲームデータ名。
   韓国側の資料から取込で作る)
4. **Rust が `format!` で組み立てて返す文(エラー文・「武器 エンチャント」)も Rust は変えない**。
   辞書(`rust.json`)に文面を穴つき(`{0} エンチャント`)で載せ、`t()` は完全一致が無いときに照合で当て、
   穴に入っていた部分(部位名など)も訳す。鍵は点検スクリプトが Rust のソースから同じ形で抜き出すので、
   Rust の文面を変えると漏れとして出る。当初は「コード + 引数を返す形に変える」予定だったが、
   API の形と文字列の突き合わせ(バフタブ)に手を入れずに済むこちらに改めた(2026-09-24)
5. **韓国語の辞書とフォントは韓国語のときだけ読む**(`loadLocale`)。ハングルは Noto Sans KR を
   日本語フォントの後ろに並べる(M PLUS はハングルを持たない)
6. **数値の書式は表示言語の Intl**(`LOCALE_TAG`)。書式の入口は format.ts だけ(R11)なので 1 か所
7. **ゲームデータ名は出典のあるものだけ入れる**(ユーザー判断 2026-09-24)。出典が無い名前は
   `names.json` に入れず、日本語のまま出す(`t()` の既定の動き)。音写・推測で埋めない。取込は
   `tools/i18n/import_names.py`(Python)。手書きの対応表を正本にせず、スクリプトを再実行すれば
   同じ結果になる(系列名の対応のような小さな規則表はスクリプト内に置く。例外はスキルの対応表で、
   韓国語の文字列ではなく対応だけを持つ。下記)
   - **装備(最優先)**: 韓国公式の確率公示「装備アイテム検索」API
     (`POST https://static.tales.nexon.com/Probability/filterItemData`、form-urlencoded。
     ブラウザの User-Agent に加え `X-Requested-With: XMLHttpRequest` /
     `Origin: https://static.tales.nexon.com` /
     `Referer: https://static.tales.nexon.com/Probability/Game/8-3` /
     `Content-Type: application/x-www-form-urlencoded; charset=UTF-8` が無いと `[]` が返る。
     `wearPart=<부위>` で武器種などの一覧、`wearPart=<부위>&equipType=<종류>` で
     `[{"ItemID": …, "ItemName": …}, …]`。部位は 갑옷/다리/렐릭(오른쪽)/렐릭(왼쪽)/머리/몸/무기/방패/손/투구
     の 9 つ、全 2,587 件、2026-09-25 確認)。**ItemID = 日本版クライアントの ItemId**。
     crates/gamedata の装備行のうち client.rs 由来(出典に `ItemId <id>` を持つ)は出典から直接、
     それ以外(generated.rs / items.rs / sacred_kr.rs 等)は日本版クライアント DB
     (`C:\github\private\tw_assets\db` の CSV 群。環境変数 `TW_ASSETS` で場所を切替。
     `dm_00000_9NNNN.csv` は本編テーブルの影の複製〔ItemId が +9000万オフセットの別データ〕なので除く)
     から**日本語名が一意に引ける場合だけ** ItemId を得て照合する。2026-09-25 時点で
     ItemId 直接 623 件・DB 経由 20 件(装備カタログ全体の一部。古い/廃止装備は韓国公式の現行
     一覧に無いことが多く候補なし)。韓国語名の頭の記号(†)は日本語名の頭が † のときだけ足す
   - **装備(フォールバック)**: 韓国コミュニティの装備整理シート(Google スプレッドシート
     `1rT24bRdfsqcX3N4JbRx1dZhqyEAf5OcAPnwPerd18Ds`、`sacred_kr.rs` と同じ出典。認証なしに
     `.../export?format=xlsx` で取れる)の武器・防具タブを、crates/gamedata の統合後カタログと
     **9 値(values_min/values_max)の完全一致 + 系列名の音の対応**(인퍼널→インファーナル、
     세크리드→セイクリッド 等)で照合する。候補が 0 件・複数残る・系列が合わないものは入れない。
     ItemId を持つ韓国側データは見つかっていないので、名前と数値だけで照合する。
     公式 API と食い違ったら API を採る(2026-09-25 時点で食い違いは無し)
   - **装備アビリティ**(シートの「어빌리티」タブ、韓国公式の確率公示
     `https://static.tales.nexon.com/Probability/Game/6-1`〜`6-5` も検討)は確実な照合キーが無いため
     今回も見送り。公式公示は고대 정령/심연/상실/최상급 룬석/야성 の5系統がランダム効果スロット付きの
     別構造(基本効果 + 6 択の追加効果 2 枠)で、crates/gamedata 側の `(下)/(中)/(上)` 段階制のラダー
     (`equipment_catalog/abilities.rs`)と 1 対 1 に対応しないため、系列名だけでは安全に照合できない。
     将来、韓国側に id 付きの資料か構造の対応が明確な資料が見つかったら追加する
   - **敵**: 韓国のファンサイト talesdb.xyz の `https://talesdb.xyz/assets/monsters.json`
     (42 件。이름・스탯방어・고정방어・고정피감・피감률・속성값・HP)を、crates/gamedata/src/enemies.rs
     の 42 件と **HP の完全一致**で照合する(一意に決まるものだけ。2026-09-25 時点で 27 件採用、
     候補複数 13 件・候補なし 2 件は見送り)。副次的に `defense` = スタット防御 + 固定防御、
     `damage_reduction` = -固定被ダメ減、`cut_rate_a` = 1 - 被ダメ率/100、`element_threshold` = 属性値、
     とも一致することを確認した。talesdb.xyz はライセンス表記が無いサイトなので、取得した JSON は
     `tools/i18n/cache/`(gitignore)にだけ置き、names.json に入れるのは名前だけ。生データはリポジトリに
     同梱しない
   - **バフ**(任意): talesdb.xyz の `https://talesdb.xyz/assets/buffs.json`
     (19 キャラ・58 件、キャラごとに 공격피해량/적받는피해증가/적능력치감소/추가피해량/중딜레이감소
     の 5 効果値を持つ)は、`crates/gamedata` の `character_skills.rs`(キャラ固有バフ。攻撃力%・被ダメ
     増減%など)と効果の種類・数値で対応しそうな組が確認できた(例: 루시안の「강검」5%攻撃力増加 ↔
     `lucian_iron_wall`〈鉄壁〉+5%、「산들바람」5%被ダメ増加 ↔ `lucian_breeze`〈そよ風〉-5%)ものの、
     KR 側の効果 5 種と JP 側の `DamageCategory` 効果種の対応表を安全に作るには時間が要り、
     今回の段階 4 では見送った。将来、対応表(KR 効果キー → JP DamageCategory)を作れたら追加する
   - **キャラ**: 韓国公式のキャラ一覧 `https://tales.nexon.com/About/Character`(ブラウザの
     User-Agent で取れる静的 HTML。19 キャラの韓国語名 + 英語名 + URL スラッグ)を
     `crates/gamedata/src/characters.rs` の 19 人と id で突き合わせる
   - **スキル**(攻撃スキル・キャラスキル): 韓国公式のキャラ別スキル記事(`https://tales.nexon.com/About/Character/<Slug>`。
     ブラウザの User-Agent に加え `Referer: https://tales.nexon.com/` が無いと 403 になる)。
     ページのタブ一覧 `<ul id="character_about_list">` から「스킬」を含むタブの記事番号を取り、
     `https://tales.nexon.com/About/Character/<記事番号>`(JSON `resultValue.content` が本文 HTML)
     から技の見出しを取る。**倍率・打撃数は日韓で合わないことが多い**(公式記事が古い・サーバーごとの
     調整)ので数値では照合できず(完全一致では 35 件・誤対応あり)、**どの日本語スキルが公式のどの
     名前かの対応だけ**を `tools/i18n/skill_pairs.json`(スキル id → 公式の韓国語名)に持つ
     (ユーザー判断 2026-09-24)。対応は Claude が名前の音・漢字・意味・系列で付け、Codex がレビューする。
     韓国語の文字列はすべて公式由来で、取込は表の名前がそのキャラの公式記事に実在しなければ止まる。
     極限スキルは `극·` を前に付ける(「極・ダメージプラス → 극·대미지 플러스」にそろえる)。
     公式本文の互換漢字(連 = U+F99A)は NFC にそろえる。同じ日本語名がキャラによって別の韓国語名に
     なる場合は 1 つしか持てないので、音の合う方を採る。公式記事に無いスキル(新しいスキル・
     イェフネン)と**マスタリー**(公式記事に載っていない)は日本語のまま
     当初検討した 나무위키(NamuWiki、敵の出典候補)は Cloudflare のボット対策で機械取得できず不採用。
     敵の出典は上記の talesdb.xyz に差し替え済み(2026-09-25)
   - 画面に出る名前・説明文は `cargo test -p gamedata --test dump_names -- --ignored dump_names`
     で `tools/i18n/out/*.json`(gitignore)に書き出せる。取込スクリプトと説明文の訳の材料
8. **ゲームデータの説明文(note 類)は訳す**(`notes.json`、約 880 件)。固有名ではなく文章なので
   画面の文言と同じ扱い: Claude が訳して Codex がレビューし、確度「高」を反映する。文中の固有名は
   辞書(`names.json` ほか)に韓国語があればそれを使い、無ければ日本語のまま残す(名前の表示と揃える)。
   鍵は Rust の原文なので、原文を変えると訳が外れて日本語に戻る(点検スクリプトは数えない)
9. **「wiki に聞く」は対象外**。一次ソースの Tale Wiki が日本語だけで、答えも日本語の文面を引用する

## 段階

1. 土台: `i18n.ts`・言語の段・format.ts・labels.ts・情報パネル・点検スクリプト
2. Rust が返す文言(`rust.json`、穴つきの照合)
3. 画面の文言を `t()` に(ホーム → キャラ → 計算 → バフ → 残り)
4. ゲームデータ名(`names.json`)と説明文(`notes.json`)。2026-09-24 完了。2026-09-25 に追加出典
   (装備は韓国公式の確率公示 API を最優先に、敵は talesdb.xyz を追加)で収録件数を拡大。
   名前は装備・キャラ・スキル(公式記事にあるもの)・敵(HP が一意なもの)を収録、装備アビリティ・
   マスタリー・バフ(キャラ固有)は確実な照合キー/対応表が無く未収録

## 却下した選択肢

- **i18n ライブラリ(paraglide-js / svelte-i18n / typesafe-i18n)**: 言語は 2 つで、切り替えは読み込み直し。
  必要なのは辞書を引く 1 関数だけで、コード生成やストアを足す理由が無い
- **意味の鍵(`about.title`)+ 型で漏れを防ぐ**: 画面のソースが読めなくなり、Rust の表示名を訳すには
  Rust 側にも鍵を持たせる必要がある。漏れの検出は点検スクリプトで足りる
- **Rust に言語を渡して Rust が訳す**: domain に表示の都合を持ち込む。訳は画面の仕事
- **切り替えをその場で反映(リアクティブ)**: 滅多に切り替えないものに、全画面の文言をリアクティブにする
  費用を払わない
