# ADR-021: 出典の格付けと訂正の層(公式お知らせ > アプリの静的データ > wiki)

- ステータス: 採用
- 期間: 2026-09-22 〜
- 関連: ADR-017(バフ・デバフの値は公式お知らせ > wiki)、ADR-020(wiki に聞く)、Issue #36

## 背景

ADR-017 は「バフ・デバフの数値は公式お知らせが wiki より上」までを決めた。「wiki に聞く」は wiki の
文面をそのまま候補として LLM に見せ、画面に描く。wiki が間違っているところ(ADR-017 の表: マキシミンの
毒舌は効果が逆、など)をそのまま答えると、ゼリッピの答えと計算タブの数字が食い違う。
アプリはクライアント DB 由来の装備の 9 値・上限、称号など、wiki に無い・wiki より新しい静的データも持つ。

## 決定

1. **格付けは 公式お知らせ > アプリの静的データ > wiki**。ADR-017 の順序を静的データまで広げる。
   「アプリの静的データ」は crates/gamedata(クライアント DB 由来の装備・称号、公式お知らせから
   起こしたバフ・スキルの値)を指す
2. **wiki の値は消さない。並べて出す。** 画面は「wiki にはこう書いてあるけど、公式お知らせではこうッピ」の
   形で、wiki の値に取り消し線、訂正後の値、出典リンクを重ねて描く。理由: 消すと wiki を見た人が
   「違うことが書いてある」で信用を失い、どちらが正しいかを読む人が確かめられない
3. **訂正はデータ(`correction` 表)で、当てるのはコード**。LLM は値を書かないので、候補に訂正後の値を
   入れておけば結論文の `{{札.列}}` も自動で訂正後になる。LLM に「wiki は間違っている」と判断させない
4. **確かさ(`grade`)は 2 段**。`confirmed`(公式お知らせ、人が確かめた静的データ)は言い切る口調。
   `apparent`(取込のたびに gamedata と wiki の行を機械で突き合わせた食い違い)は「〜みたい」の推量。
   段階 1 で入れるのは `confirmed` の公式お知らせ由来だけ。`apparent` は段階 3
5. **訂正の正本は gamedata**。`crates/gamedata/src/bin/export_corrections.rs` が `CharacterSkillDef` /
   `BuffDefinition` のうち `source_url` が公式お知らせ(`talesweaver.nexon.co.jp`)のものを JSON
   (`tools/gamedata/wiki/corrections.json`、生成物)に書き出す。値の文字列は効果値から機械で作り、
   手で書かない。二重管理にしない
6. **wiki の行との結び付けは取込(units.py)で行う**。`page`(`Skill/<キャラ名>`)の row ユニットのうち、
   行の名前の列(row_key)に `match`(スキル名)があり、`subject` の変種名(【暴言】)も本文にある行を選ぶ。
   説明文の中で他のスキル名に触れている行に付かないよう、名前の列を先に見る。無ければ `unit_id` は
   NULL で、その訂正は単独の候補になる(迅速の秘薬のように wiki にエントリが無いもの)
7. **公式お知らせは URL を必ず持つ**(`CHECK (source_kind <> 'notice' OR source_url IS NOT NULL)`)。
   `source_title` も URL の `no=` から機械で作る
8. **ユーザーの報告(「この値は違う」)は訂正に直接入らない**。確認されて初めて `confirmed` になる。
   未確認の報告は誰の画面にも出さない(段階 3 の `value_wrong`、issue-triage の手順に載せる)

## 却下した選択肢

- LLM に公式お知らせの文面も渡して「どちらが正しいか」を判断させる: 画面に出る値を LLM が書かない
  原則に反する。訂正はデータとコードで当てる
- wiki の値を訂正後の値で上書きして 1 つだけ出す: 決定 2 の理由で却下
- 訂正を手書きの JSON で持つ: gamedata と二重管理になり、計算タブとゼリッピの答えがずれうる

## 実測(2026-09-22)

gamedata から書き出せた公式お知らせ由来の訂正は 25 件(キャラスキル 22 + 消費アイテム 3)。
wiki の行に結び付いたのは 21 件。結び付かない 4 件は wiki に項目が無い(消費アイテム 3 件)か表記が違う
(ミラ カードスプレーA)。ADR-017 の表にある「毒舌(基本)」「棒のように振るう剣」は gamedata に収録して
いない(前者は計算経路が無い、後者は `MasteryDef` が `source_url` を持たない)ので訂正にも出ない。
出したいなら gamedata 側に値と出典を持たせるのが先。

## 残っていること

- `apparent`(自動検出)の突合規則と、人が `confirmed` に上げる運用(段階 3)
- クライアント DB 由来の装備・称号の値を「静的データだけの項目」として出す形(段階 3)
- `MasteryDef` に `source_url` を持たせるか(棒のように振るう剣の訂正を出すため)
