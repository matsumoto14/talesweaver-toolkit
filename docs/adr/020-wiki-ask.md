# ADR-020: wiki に聞く(ゼリッピが出典つきで答える)

- ステータス: 採用(段階 0〜3 実装済み。回す道と K=3 投票だけ評価(実 API)待ち)
- 期間: 2026-09-22 〜
- 関連: Issue #36(唯一の起点。設計案の要点を写してある)、ADR-013(本文を持たない)、ADR-017(出典の格付け)

## 背景

Tale Wiki を情報源に、案内役ゼリッピが対話の形で初心者の質問に出典つきで答える機能。
ADR-013 の段階 3(サーバーの索引と AI 相談)に当たる。設計案(2026-09-22、独立レビュー反映済み)の
決定事項は Issue #36「決めたこと」が正で、ここには**実装しながら決めた・変えたこと**だけを書く。

段階の番号はこの機能の中の順番(0 = LLM なし検索、1 = 理解 + 選択、2 = 回す道と続き、3 = 仕上げ)で、
ADR-013 の段階 0〜5 とは別。

## 決定(段階 0、2026-09-22)

### 経路と名前

1. **ホスト名は `api.tw-context.dev`、CSP は明示 1 件追加**(ユーザー決定)。`https://*.tw-context.dev` の
   ワイルドカードは採らない。理由: 既存の `inquiry` と同じく許可先が読める形にする。Worker を足すたびに
   リリースが要るが、それは inquiry でも同じで、頻度が低い
2. inquiry とは別 Worker(`services/api-worker`、Worker 名 `tw-context-api`)・別 D1(`tw-wiki`)。秘密も
   レート制限の単位も違い、片方の障害をもう片方に持ち込まない

### 単位(ユニット)

3. **箇条書きは項目ごとに 1 ユニット**(ユーザー決定)。ADR-013 の「見出し + 数行の断片まで」に収まる扱いで、
   表の行と同じ。上限は段落と同じ 3 文・200 字。同じ箇条書きの項目は `group_key` で 1 塊
4. **縦見出しの表(`|~条件|Lv35以上|`)は「項目 | 内容」の行にする**。クエストページの条件・報酬・概要が
   この形で、列名を持たない。`|~|続き|` は上の項目に続け、`|>||` の区切り行は捨てる。
   列名の組にならない表を無理に行にすると `列1: | 列2:` のような空の行が大量に出る(実測)
5. **値が 1 つも無い行・記号だけの段落(`-`、`&nbsp;`、`----`)はユニットにしない**
6. **unit にしないページ**: コメント(`コメント/`、`Comments/`、`*/1LineBBS`)、ナビ(`MenuBar*`、`Menu2`)、
   wiki 自身の運用ページ(`PukiWiki/`、`練習用ページ`、`SandBox`、`InterWiki*` など)、古い告知の転載(`公式告知*`)。
   ADR-013「コメント・wiki 編集・MenuBar 類は抽出・案内に使わない」の適用。page 表には載せる。
   規則は `tools/gamedata/wiki/units.py` の定数 1 か所
7. 出典 URL の EUC-JP パーセント符号化は Python(取込)で作って `page.url` に保存し、Worker は
   `page.url + '#' + anchor` を連結するだけ。TextEncoder は EUC-JP を出せない

### 索引と検索

8. **`unit_fts` は contentless(`content=''`)+ `detail='full'`**。Issue #36 の「detail='none'」から変えた。
   実測で `detail='none'` と `'column'` は bm25 が常に 0 になり順位が付かず、rowid 順の 40 件を切るので
   再現率がほぼ 0 になった。本文を持たない担保は **terms を取込時に重複を落としてソートした語の集合に
   する**ことで保つ — 位置情報があっても語順・出現回数は復元できない(reviewer も確認)。
   `detail='full'` に戻すことで ページ名あり 88% / 言い換え 47%(上位 20 件、後述)
9. **分かち書きは辞書語の最長一致 → `Intl.Segmenter`**。Node 24 と workerd で切れ目は完全一致(実測)。
   ただし素の Segmenter はカタカナ複合語を割る(マーキュリアルコア → マ/ー/キ/ュ/リアル/コア、
   ダンジョン → ダン/ジョン)ので、辞書が必須。辞書 = alias 全件 + ゲームの一般語 `BASE_WORDS`
   (`segment.ts`)。語末の長音の折り畳み(サーバー → サーバ)は**語単位**(`fold`)で掛ける。
   文字列全体に掛けると「ドライバーって」のように後ろにひらがなが続くと落ちず、索引と食い違う(実測)
10. **alias は (name, page) を主キー**にし、パス末尾が複数ページで衝突しても別名にする(上限 3 ページ)。
    衝突で落とすと辞書からも消えて分かち書きが壊れる(「マキシミン」→ マキシ/ミン)。多数のページに付く
    末尾(「共通」「navi」)は別名にしない
11. 段階 0 の `/search` は bm25 順の上に「語が別名に完全一致するページ」を先頭に寄せ、1 ページ 8 件で
    抑える(暫定。段階 1 では理解の段が選んだページへの加点に置き換わる)
12. 1 INSERT 文は 90 KB 未満(D1 の上限 100 KB は境界ぴったりで `SQLITE_TOOBIG`)。ローカル D1 は
    リポ内でだけ動く(長いパスで workerd が internal error)

### 画面

13. 段階 0 は静止画 1 枚(f008)+ 定型文(考え中 / 見つからない / 0 件 / つながらない)。表情 4 つの器と
    残りのコマ(f020 / f025 / f033)は置いてあり、段階 2 で割り当てる
14. 検索結果には必ず出典リンクを付ける(ADR-013 ゴール 4)。続きがあるときだけ文言を「続きを wiki で読む」にする
15. Svelte 5 の `$state` 配列に push した元オブジェクトを書き換えても画面は更新されない。配列の中の proxy を
    取り直して書き換える(実機で「考え中」のまま止まった原因)

## 決定(段階 1、2026-09-22)

16. **応答は素の JSON**。SSE は「進み具合の一言」を出す段階 2 で被せる。応答 JSON の形は段階 3 まで変えない
17. **キャラ状態は送らない(`state: {}`)**。登録キャラは素のレベルを持たず(アプリはカンスト前提)、
    `awakening.eternal_level` はエタ Lv で wiki の「Lv」とは別物。進化段階もコア 24 枠で 1 値に落とせない。
    状態での絞り込み(`conflictsWithState`)と「あなたは Lv N」のバッジは器だけ残し、保存形にレベルが入ったら詰める
18. **理解の欄は 4 つ**(kind / pages / terms / hops)。気分・困りごとの型・観点は段階 3、続きの判定は段階 2
19. **モデルは理解・選択とも Haiku 4.5**、thinking なし、キャッシュなし。理解は 4 秒で諦めてコード経路、
    選択は 15 秒・失敗時 1 回だけ再試行して 502(該当なしには化かさない)。`stop_reason: refusal` は該当なし
20. **認証は PoW → 1 時間の HMAC セッショントークン**(KV に持たない。失効は自然失効のみ)。nonce の使用済みは KV。
    連打は Rate Limiting バインディング(1 分 10)、1 日 100 問は KV カウンタ。連打と 1 日の上限は文言を分ける
21. **AI Gateway は任意**(`AI_GATEWAY_URL` が空なら直接)。毎回 `cf-aig-collect-log: false` を付けて質問文をログに残さない。
    費用上限は Anthropic Console の鍵側
22. **`cells` は wiki の生値のまま返し、訂正は `corrections[]` に wiki 値と訂正後の両方を載せる**。画面が重ねて描く(ADR-021)。
    LLM に見せる候補の値だけ訂正後にする(結論文の `{{札.列}}` が訂正後で埋まるように)
23. **キー列(表の先頭列)は選ばれた列に常に含める**。同じ表の行を候補に足すときは当たった行を中心に 25 行
24. **リアクションは答えの ID につき 1 種類**。同じ種類の 2 回目は理由チップと同意した質問文の追記、違う種類は無視
25. 応答に `missing`(候補に無かった観点)/ `verdict` / `basis` を載せる。画面は `missing` を定型文にする。
    `basis` の「根拠」印は段階 2 で

## 決定(段階 2・3 の評価に依存しない部分、2026-09-22)

26. **SSE は `Accept: text/event-stream` のときだけ**。`progress`(understand / search / select)→ `result` の順。理解より前のエラー
    (401/429/503)は SSE を始める前に HTTP ステータスで返し、Claude 呼び出し後の 502 だけ `event: error`。Accept が無ければ
    素の JSON(評価スクリプトと curl 用)。WebView2 とブラウザで `fetch` + `ReadableStream` で読めることを実測(CORS ヘッダが
    無いとブラウザ側だけ落ちる。curl では気づけない)
27. **続きの判定は理解の `followup`**(欄は 5 つに)。`prev` は直前の質問文(200 字)とページ名(100 字)だけ。ページが実在しなければ
    無効。続きとして答えたときは応答に `followup: { page }` を載せ、画面は末尾の名前でバッジ「〜の続きとして答えたよ」+ ×
    (× は `prev` 無しで聞き直し、新しいターンとして下に積む)
28. **次の一手は `unit_link` から**(選ばれたユニット内の `[[リンク]]`)。page 表に実在し、自ページでないものを出現順に 3 件。
    質問文は定型「「<名前>」はどこで手に入る?」の 1 種で、`page` はフルパス(続きの加点に使う)
29. **「この値は違う」は列ごとに 1 回**(KV キーは `[answer_id, unit_id, col]` の JSON。区切り文字で潰れない)。押した瞬間に送り、
    正しい値・根拠・同意した質問文は **確定(blur / Enter)のときだけ**追記で再送する(1 文字ごとに送ると 1 日の上限を食う)。
    `unit_id` は `p:` / `r:` の形、`col` は 80 字まで
30. `hops: multi` は `dropped` に記録するだけ(`route` は cheap のまま)。回す道を足すかの評価材料
31. 表情 4 つを割り当て(答えた f008 / 考え中 f020 / 見つからない f025 / つながらない f033)。`basis` の行に「根拠」の印

## 決定(段階 3、2026-09-22)

32. **困りごとの型「勝てない」は最小版**。理解の欄に `mood` / `trouble` を足し(7 つ)、`trouble = cant_win` なら応答に
    `playbook: "cant_win"`(wiki の答えが none でも載せる)。**打ち手は端末が描く**(装備の中身を送らない):
    攻撃側はクリティカル率の供給源 4 つ(ペット会心 → 致命打 → 極ルーン → 研究室、費用の安い順)の使用 / 未使用、
    防御側は `preview_defense` の現在値(物理側)+ 費用の安い順の定型文 4 行。domain に防御側の
    「次にできること」は無いので、段階 3 では定型文まで。クリティカル率そのものは計算タブの対象があるときだけ
33. **静的データだけの項目(称号・装備)は `correction` 表に `unit_id NULL` の行として載せる**(1 セル 1 行、
    `c:app/<名前>/<列>`、`section` 列を追加)。別表・新しい候補の種類は作らない。書き出しは
    `crates/gamedata/src/bin/export_app_data.rs` → `tools/gamedata/wiki/app_data.json`(称号 364 + 装備 1,308 件、
    R2 のテネブリスは含めない)。候補に載るのは**質問の語が名前に完全一致したときだけ**(最大 3 件)。
    そのために名前を分かち書きの辞書に入れる(取込の dict.txt と Worker の `loadAliasIndex` の両方。alias 表には入れない =
    ページ候補を汚さない)。出典は「アプリのデータ」で URL は null
34. **自動検出の訂正(`apparent`)は装備の 9 値だけ**。wiki の装備表(`Item/武器/*` `Item/防具/*` `Item/アクセサリ/*`)は
    名前を横結合の 1 行に単独で書くので、取込で「名前行 → 後続の数値行」に `名前` 列(先頭 = キー列)として伝播し、
    `~` 装飾の行を列名に昇格してから、app_data の値と比べる。`-` / MAX / % / 範囲は比べない。
    実測: 65 ページ中 64 で伝播、名前一致 795 行、比べられたセル 160、食い違い 0 件(誤検出 0)。
    比べられるセルが少ないのは、wiki 側が範囲(`85-90`)で書く列が多いため
35. 称号の条件付き追加ダメージの条件(地域・敵)は日本語のラベルにして出す(内部の enum 名を出さない)

## 評価(段階 0、2026-09-22)

評価セット `services/api-worker/eval/questions.json`(wiki 50 問 + 言い換え 15 + 雑談 5 + 範囲外 5 + 続き 5 + wiki に無い 5)。
`eval/run.ts` が起動中の Worker の `/search` を叩き、上位 20 件に期待ユニット / 期待ページが入る率を出す。

| 群 | ユニット | ページ |
|---|---|---|
| wiki(ページ名あり)50 問 | 88% | 96% |
| wiki(言い換え)15 問 | 47% | 53% |
| 続きの質問 5 問 | 20% | 20% |

- ベクトル検索(Vectorize)は**段階 0 では足さない**。言い換えの取りこぼしは段階 1 の「理解」
  (LLM が検索語を言い換える)が担う設計なので、理解あり / なしで再測定してから決める
- 続きの質問は `prev` を使う段階 2 まで測れない(前のページ名が無い)

## 却下した選択肢

- `detail='none'` のまま順位を語の一致数で付ける: 語ごとに MATCH して数える必要があり、一般語
  (「クエスト」)が数万行に当たる。D1 の読み取り行数に直撃するので却下
- 衝突した別名を「先勝ち」で 1 ページに寄せる: 別のページが引けなくなる。複数ページに紐づける方が素直
- 表情 4 つを段階 0 から出す: Issue の「初期は静止画 1 枚」に従う。仕組みだけ残す
- 縦見出しの表を段落にする: 「条件: Lv35以上」の形は行の方が LLM にも画面にも扱いやすい

## 残っていること

- 段階 1 の評価(実 API): 行の一致率・該当なし率・口調・安い道で解けなかった率。回す道(段階 2)を足すかはその数字で決める
- 評価待ち: 回す道(`agent.ts`)、順序頑健性が低ければ K=3 投票
- 先送り: キャラ状態(レベル・進化)、防御側の「次にできること」(domain)、称号の効果の wiki 突合
- リモート D1 への投入と Worker の deploy、秘密の投入は手で行う(`services/api-worker/README.md`)
