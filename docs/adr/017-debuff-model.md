# ADR-017: 敵にかけるデバフと出典の格付け

- ステータス: 採用
- 期間: 2026-09-18〜

## 背景

自分を強くする側(パッシブ・自己バフ・味方バフ)だけが実装されていて、敵を弱くする側が
型・データ・計算のどこにも無かった。`SkillAudience` は `SelfOnly` / `Ally` の 2 つしか無く、
`character_skills.rs` には「デバフは**対象の**攻撃ダメージを上げるものなので収録しない」という
除外コメントが置かれ、`docs/damage-formula.md` も能力値倍率B の減少を「未収録(敵にかけるデバフ)」
としていた。

きっかけはユーザーの指摘「デバフがないかも。マキシミンの毒舌とか」。実際 `masteries.rs` には
マキシミン M2(侮辱 / 皮肉 / 暴言)が `RecordOnly` で「<毒舌>に〜を追加」という note だけを持ち、
肝心の `毒舌` 本体がカタログに存在しなかった。

## 決定

### 出典の格付け: 公式お知らせ > Tale Wiki

- **バフ・デバフの数値は、テイルズウィーバー公式お知らせを Tale Wiki より上に置く**(ユーザー決定 2026-09-18)。
  一次ソースは
  [システム・キャラクターバランシング実施のお知らせ(2024-02-21)](https://talesweaver.nexon.co.jp/notice/notice.aspx?no=153335)
  §6「バフ、デバフスキル効果調整」で、全キャラのバフ・デバフの変更後の値が 1 つの表にある。
- wiki はカテゴリ別(どの層に載るか)の構造を読むのに引き続き使うが、**値が食い違ったらお知らせが正**。
  お知らせは HTML ページなので `curl` + タグ除去で取れる(EUC-JP の PukiWiki を扱う `talewiki-fetch`
  skill は不要)。

**記載漏れの例も同じ扱い**(2026-09-19)。消費アイテム 3 件の「全属性 +15」は wiki(ステータス
#jc16a054・Item/消耗品/ステータス補助)に一切載っていないが、公式お知らせには明記がある:
[no=151355](https://talesweaver.nexon.co.jp/notice/newest.aspx?no=151355)(イルミネーション祭りの
ドリンク・迅速の秘薬)、[no=151524](https://talesweaver.nexon.co.jp/notice/newest.aspx?no=151524)
(ユキダルマン族の特製ポーション)。**迅速の秘薬は wiki にエントリ自体が無い**ので、お知らせだけが
出典になる。値の食い違いだけでなく、wiki に無いものもお知らせから拾う。

属性はステの器(`BuffTarget` = 全ステ / 個別ステ / ユーザー選択)で表せないので、
`BuffDefinition::element_bonus`(全属性への加算)という**副次効果の欄**を足して持つ。
`damage_effects` と同じ形で、主効果(全ステ +30% など)と両立する。`BuffTarget` に属性の
バリアントを足す案は、全ステと属性の両方を持つ 2 件が 1 エントリに収まらないので却下した。

wiki が実際に間違っていた例(いずれもお知らせで訂正):

| | wiki | 公式お知らせ |
|---|---|---|
| マキシミン 毒舌(基本) | 敵の被ダメージ +10% | **敵攻撃ダメージ −10%** |
| マキシミン 毒舌【暴言】 | 最終ダメージ −10% | **敵被ダメージ +10%** |
| ベンヤ フォース・オブ・ルベルト | 能力値倍率B −10%(自分のデメリットか敵デバフか不明) | **敵被ダメージ +10%**(敵デバフで確定) |
| マキシミン【棒のように振るう剣】 | スキル説明は「防御力 −7% とみなす」 | **防御無視確率 +15%** |

つまり **毒舌の基本効果は自分の火力に入らない**。火力に入るのは【暴言】を取ったときの +10% だけで、
wiki の読みでは効果が逆になっていた。

### デバフは 2 種類に割れる

お知らせの語彙がそのまま分類になる。

- **敵被ダメージ増加 X%** — 自分の与ダメージが増える。**収録する**(22 件)
- **敵攻撃ダメージ減少 X%** — 敵が自分に与えるダメージが減る。**収録しない**。
  「敵が攻撃してくる」計算経路自体が存在しない(`calculate_damage` は常にプレイヤー → 敵の一方向、
  `defense.rs` の対人は命中率/回避率だけでダメージ交換を計算していない)

### 敵被ダメージ増加は新しい器を要らない

与ダメージ式の **S 項(`DamageCategory::TakenDamageReduction`、式中の `(1−S)`)は既に生きていて、
供給源がゼロだっただけ**だった。デバフはここに負値で入る:

```
Σ = −0.10 → get() が 1 − (−0.10) = 1.10 = 「敵被ダメージ +10%」
```

- **新しい `DamageCategory` も新しい `SkillEffect` variant も作らない**。敵専用のステ計算パイプラインも
  作らない(`Enemy` は集計済みの最終値しか持たず、層を通して積む構造になっていない)。
- `TakenDamageReduction` の上限・下限を `range(-0.30, 0.30)` にする。出典は wiki ステータス
  [S4]被ダメージ減少(スキル)。それまで `None` だった。
- `is_effort()`(「一番効いている / 次に伸ばす」の候補)から `TakenDamageReduction` を**外す**。
  敵側カテゴリは候補にしない、という元の分類は「プレイヤーが動かせないから」が理由だったが、
  デバフは S を動かせる唯一の手段なので前提が変わった。

### `SkillAudience::Enemy`

- 敵にかけるデバフ。`Ally` と同じく**誰でも ON にできる**(同行者がかける前提)。
- `Ally` と同じく**マスタリーの差し替えを見ない**。相手のマスタリー選択は分からないため。
- 結果として、マスタリー依存のデバフ(毒舌【暴言】、カース・ペンジュラム【シンボルオブスピリット】等)は
  **マスタリー名を含んだ独立エントリ**として収録する。「パーティのマキシミンが暴言型の毒舌を撒いている」は
  プレイヤーにとって ON/OFF できる事実であって、自分のマスタリー選択ではない。
- `masteries.rs` 側の該当マスタリーは `RecordOnly` のまま据え置き、note で
  「効果は character_skills.rs の側が持つ」と書く。二重計上を防ぐため。

### 保存形は変えない

`CharacterSkills::skill_ids` は `Vec<String>` なので、カタログに id を足すだけで既存キャラも読める。
`SCHEMA_VERSION`(17)も IndexedDB(7)も据え置き。マイグレーション不要。

## 収録しなかったもの(理由つき)

- **敵攻撃ダメージ減少**(毒舌の基本効果 −10%、シベリン嘲笑、ティチエル/クロエ/ノクターン感電、
  ランジエ麻酔弾、イサック戦場の化身、ミラ覇気、ナヤトレイ中毒、リーチェ虚弱、イェフネン ボリス! 等):
  消費側が無い。やるなら「相手が自分に与えるダメージ」という新しい計算方向を立てる別 goal。
- **毒舌【侮辱】の能力値 −10%**: 敵の防御力を「ステータス防御 + 固定防御」に割る必要がある。
  wiki は「攻撃対象の防御力(ステータス)を下げるデバフ。防御力(固定値)には影響しない」と明記しているが、
  `Enemy.defense` は合算 1 本(ADR-003)。合算値に −10% を掛けると効果を過大評価する。
- **毒舌【皮肉】の最小命中率 −10%**: 同じく被弾側(命中率下限 = 15 + 攻撃者の最小命中率補正 −
  攻撃対象の最小回避率補正)。

## 却下した案

- **`Enemy` に生ステータスを持たせて層を通す**: ADR-003 が「防御力はステータス防御+固定防御に分解される」と
  書きつつ実装を合算 1 本で確定させた判断を覆すことになり、敵 42 体全件のデータ再構成が要る。
  デバフのために見合わない。
- **C 項(敵防御)に割合減少カテゴリを新設**: 上と同じ理由で、掛ける対象(ステータス防御分)を
  分離できない以上、新設しても正しい値にならない。

## 残した設計債務

`TakenDamageReduction` の cap `range(-0.30, 0.30)` は wiki の **S4(スキル)** の上下限だが、
実装は S を 1 カテゴリで持っているので**集計後の S 全体**に掛かる。S1 秘薬(+20%)・S2 一般(+15%)・
S3 基本発動(+15%)・S5 その他の供給源を将来足すと、本来の合算上限(最大 +50% 程度)より厳しく
clamp される。**いま S1〜S3 / S5 の供給源は 1 つも無い**ので実害は無い。足すときに X(攻撃ダメージ)と
同じ親子構成へ割る。

## 直したもの(レビュー指摘、2026-09-18)

- **画面のラベルは TS 側が実体**だった。`SkillEffect::label()`(Rust)はテストからしか呼ばれておらず、
  画面は `characterSkills.ts` の `singleEffectLabel` を通る。S に負値を載せると
  「被ダメージ減少 −10%」という**意味が逆に読める**文字列が主表示に出ていた。両方に
  「敵被ダメージ +10%」への読み替えを入れた。ついでに符号を潰す `+{percent}` を直した
  (減少効果が `+-10%` になっていた)
- **伸ばす方向はカテゴリで違う**。`damage_levers` の上限判定と伸びしろ、TS の `catAtCap` / `catLoss` は
  `cap.max` しか見ておらず、下限に張り付いたデバフが「まだ 60% 伸ばせます」と嘘をついていた。
  `CategoryTrace` に `subtractive` を足し、減算系は `cap.min` 側で測る
- **`CharacterSkillDef::exclusive_with` を追加**。同じスキルの強さ違いを別エントリで持つと
  (カース・ペンジュラムの通常と【シンボルオブスピリット】)両方 ON にできて二重計上する。
  押した方を採って相手を落とし、保存データは `validate()` で弾く
