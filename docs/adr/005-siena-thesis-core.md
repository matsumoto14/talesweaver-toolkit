# ADR-005: シエナのオーラとテシスコア

- ステータス: 採用
- 期間: 2026-08-24〜2026-08-27
- 元文書: goals/2026-08-24-siena-thesis.md、goals/2026-08-27-siena-registration.md(git 履歴参照)

## 背景

キャラタブでグレー「これから」だったシエナのオーラ・テシスコアを wiki 出典でドメインモデルに追加する。wiki「装備システム/シエナのオーラ」を調べたところ、段階ごとの解放スロット数だけが固定値で、中身の能力値は再抽選のランダム値だった。静的データとして同梱できる値が無いため、ユーザーに実測値を入力させる例外モデルが必要になった。テシスコアは swiki のコンテンツ入場条件「コア 60/120/210/300/480」が何を指すか不明のまま注記どまりになっていた。

## 決定

### シエナのオーラ

- 対象は Lv310 の**8 部位**(兜/鎧/武器/盾/頭/体/手/足)。盾+/効果/AF/レリックは対象外(wiki「装備システム」冒頭表の「オーラ」行)
- 配線は wiki の記述どおり3経路: 武器/盾の能力値(突き/斬り/魔攻/魔防/物理複合/魔法斬り)は「装備補正(エンチャント扱い)」= **強化能力値**、その他部位の STAB〜AGI と追加オプション「全ステータス増加」は**最終固定値層**、追加オプション「攻撃力増加」は**New1**(`SienaAuraAttackRate`)、追加オプション「クリティカル確率」は AGI 由来項に乗算(`#CriticalChance` の式より)
- 複合能力値(物理複合・魔法斬り)は domain が分解する(大きいほうが先、`(value + 1) / 2`)
- 入力粒度は**スロットを1個ずつ選んで積む**(`SienaAura { slots, extras }`)。増幅段階は `slots.len()` と定義上等しく別入力にしない。追加オプション枠数は段階 3/7/10 で 1/2/3 個解放
- 選べる種類・値域は wiki 一覧表そのままを domain のカタログにして画面へ渡す(中身はランダムでも種類と値域は静的データ)
- 与ダメージ式に入らない種類(物理/魔法ダメージ耐性・クリティカル被撃率減少・命中率・回避率)も「記録するだけ」枠として選択可能にする。段階=実スロット数を合わせるため
- 「防御無視攻撃確率」「HP/MP/SP 増加」は収録しない
- **オーラは装備登録と独立した所持物として8部位ごとに登録・装着する**(2026-08-27、旧設計から転換。下記参照)

### テシスコア

- **装着位置 1〜6 の6枠**。タイプは**火力4種(突き/斬り/魔攻/魔防)+ 補助4種(物防/回避/敏捷/命中)の8種**。経験値タイプは持たない
- 補助タイプの値は与ダメージ式に渡さないが `SupportValues` として装備値の合計を保持する(将来、防御側・命中/回避の計算に使う)
- 進化 0〜4 × 強化 0〜4 の補正値表を保持(火力の最大値: 進化4強化4 = 80)。補助タイプは進化4の強化1以降だけ別値(45/50/55/60)
- **地域別に6枠を持ち、対象コンテンツの地域で自動切替する**。地域は**4つ(マーキュリアル洞窟/アビス/エクリプス/ルビコナ)**、シオカンヘイムは持たない(経験値タイプのみで与ダメージに効かないため)
- swiki の入場条件「コア 60/120/210/300/480」の正体は**6枠の火力補正合計**と判明。`ContentRequirement::ThesisCoreTotal` として実判定に昇格させた。判定は**そのコンテンツの地域のコアだけ**を数える(地域が無ければ 0)
- コンテンツ→地域の対応は wiki「実装済みダンジョンコア」表+ユーザー確認分。**対応が無いコンテンツはコア効果が無い**(不明ではなく確定値)。「異界の峡谷」は防衛戦がルビコナ、通常(兵士)がエクリプスで分かれる
- コアセット効果は**強化4のコアが3〜5個/6個そろうと発動**。**進化段階ごとに成立した分を合算**する(2026-08-26 決定、詳細は却下した選択肢を参照)
- セット効果は**地域をまたいで重複・加算**する(1つだけではない)
- テシスコアは `StatSources` ではなく `Equipment` に持つ(効くのが装備の強化能力値のため)

### シエナのオーラを装備と独立登録にする(2026-08-27、設計転換)

出典: wiki「装備システム/シエナのオーラ」`#w4fdd1bb`「抽出・注入」。抽出すると装備の取引属性が元に戻り、抽出済みオーラは取引・OM 利用ができ、オーラの付いていない同じ部位の装備へ注入できる。

- 旧設計「`EquipmentPart::siena` として装備登録に内包」を取り消し、`Equipment::siena` に8部位それぞれの**登録一覧+装着中ID**を持たせる。オーラは特定の装備品に固定された構成要素ではなく、抽出後も同部位用の独立した所持物として残るため
- 計算へ入るのは装着中の1件だけ(`selected_id = None` で未装着)。保存検証は登録全件に対して行い、存在しないID・重複ID・部位/値域違反を拒否する
- UI は装備登録と同じ操作語彙にする。部位一覧に登録数・装着中名称・段階・要約を出し、その場で切り替える。編集オーバーレイは背景クリックでは閉じず、「閉じる ×」か Escape だけで閉じる
- 旧データの互換移行は作らない(サービスイン前でデータ変更可というユーザー判断。旧 `EquipmentPart::siena` は削除し、新しい空の登録一覧として読む)

## 却下した選択肢

- **シエナのオーラを部位ごとの合計値入力にする**(2026-08-24 決定→2026-08-26 取り消し): 個別スロット入力は合計と計算結果が同じで入力コストだけ増えると判断していたが逆だった。段階入力欄が値欄と重複する、wiki の内訳(物理複合5=突き3+斬り2)をユーザーに計算させる、その部位に出ない能力値まで欄に出る、の3つの問題を生んでいた
- **コアセット効果は「成立する最も高い進化段階を1つだけ採る」**(2026-08-26 取り消し): 混在時(進化3強化4×3+進化4強化4×3など)に過小評価していた。さらに K(固定値)と L(割合)はダメージ規模で優劣が逆転するため「強さで選ぶ」は恣意的だった。進化段階の高い順に成立を合算する方式に変更
- **セット効果は地域内で最大1つだけ発動**: ユーザー確認により、地域をまたいで重複・加算するのが正だと判明
- **シエナのオーラの防御無視攻撃確率・HP/MP/SP増加の収録**: 防御無視は確率発動でエレメンタルブレイクと同じ理由で見送り、HP/MP/SPは与ダメージ・防御側どちらの式にも入らないため見送り
- **テシスコアの経験値タイプ・シオカンヘイム地域の収録**: 火力にもセット効果にも効かないため収録しない

## 経緯

- 2026-08-24: wiki 調査でシエナのオーラに Lv 別固定値が無いと判明し、部位ごとの合計値入力モデルで実装。テシスコアは swiki のコア入場条件の正体(6枠合計)を突き止め、地域別の実判定に昇格させた
- 2026-08-25: 追加オプションの残り(S18)を精査し、クリティカル確率を収録、防御無視攻撃確率は見送りで確定
- 2026-08-26: コアセット効果を「進化段階ごとに合算」する方式へ修正。シエナのオーラの入力を合計値からスロット単位の積み上げへ転換
- 2026-08-27: wiki の「抽出・注入」記述を発見し、シエナのオーラを装備内包から独立登録・装着へ設計転換した
