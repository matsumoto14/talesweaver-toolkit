## A. 同じラベルなのに「入れる数の意味」が 4 通り ★最優先

補正源ごとに `STAB` という同じラベルの欄が並ぶが、**入れる数の意味が全部違う**。
上限を見ないと区別できず、上限を見ても分からない。

| 補正源 | 上限 | 実際に入れる数 | 画面の注記 |
|---|---|---|---|
| 神鳥の聖物 | 40 | **段階**(1 段階 = +10) | あり「10 段階 (+100)」 |
| クラウン | 300 | **実値** | なし |
| モンスターカード | 70 | **実値** | なし |
| ルーンスキル | 20 | **Lv**(Lv = 実値) | なし |

**何が起きるか** — 「クラウンの STAB に 100」と「神鳥の聖物の STAB に 100」が
まったく別のことを意味するのに、画面上は同じ形。ユーザーが「この 100 は何?」となる。

**直し方** — 神鳥の聖物と同じように、**全部に `format` の注記を付ける**。
「段階」を入れるものはラベルを `STAB(段階)` にする。§07「値はチップの中に書く。
選ぶ = 値が確定する」の精神で、**数の意味を欄の中で言い切る**。

## B. 何の値か言えていない欄が 4 箇所

| 場所 | 表示 | 問題 |
|---|---|---|
| 計算タブ ランダムOP | `値 = 33 / 上限 33` | ラベルが「値」だけ。何の値か言っていない |
| 計算タブ 調整 | `(ラベルなし) = 0 / 上限 3,000` | 部品にラベルが無い(行見出しが左にあるが、部品としては無名) |
| キャラステータス 能力値 | `(ラベルなし) = 310 / 上限 310` | 同上(表の行見出しで STAB と分かる) |
| キャラタブ 調整 | `(ラベルなし) = 50 / 上限 3,000` | 同上 |

**直し方** — 表・行の中で見出しが左にあるものは `aria-label` だけ足せば足りる。
ランダムOP の「値」は、その OP の効果名(例「物理複合攻撃力が増加」)を出す。

## D. 「OP を追加」の形が合っていない

段階選択(セグメント)で出しているが、**これは「1 つ選ぶ」ではなく「追加する」操作**。
どの段も選ばれていない状態が正しいのに、段階選択は選択状態を前提にしている。

§08 は「**追加用のチップは破線 + ＋**。実在のチップと見た目で区別する」と決めている。
そちらの形にする。

---

## E. 段階を「値」で入れさせている

ルーンスキル(Lv 0〜20)と神鳥の聖物(0〜40 段階)は**段階**なのに、数値入力になっている。
§07 形態 2 は「段階そのものを見せる。『3』という数字を打たせない」。

ただし 21 段・41 段は横に並べきれない。エタの意志と同じ**節目 + 数値**の形にできるか、
それとも段階として並べるのを諦めるかは、節目があるかどうかで決まる(要ドメイン確認)。

## F. 上限がゲームの実態と合っているか未確認

棚卸しで見えた上限のうち、根拠が `[仮]` のもの:

- 装備補正 9 値 = 1,000(ユーザー指定。wiki に全装備共通の上限は無い)
- 調整の加算 / 固定 = ±3,000 / 3,000(検証用の安全域)
- ランダムOP の値 = OP ごと(`random_option_value_max` が `[仮]`)

## 対応の順序(案)

1. **A**(意味が 4 通り)— 一番混乱する。注記を全部に付ける
2. **B**(何の値か言えていない)— 小さい。`aria-label` と OP 名
3. **C のアビリティ**(8 択 × 4)— 段階選択にする
4. **D**(OP を追加)— 破線 + ＋ のチップに
5. **E**(段階を値で入れさせている)— 節目があるかドメイン確認してから
6. **C のキャラ / 主軸スキル**、**F** — 保留(§14 の E に集約)
