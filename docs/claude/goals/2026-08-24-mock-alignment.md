# Goal: デザインモック整合(v4 プロトタイプ / Redesign 規格シート との差分解消)

状態: **段階 1・2 完了(2026-08-25)/ 段階 3 以降は未着手**

## 目的

`docs/mock/Repo UI mockup directions/` の 2 モックと現状 UI を突き合わせて出た差分を埋める。

- `TW Toolkit Prototype v4.dc.html` — 動く全体像(3 タブ + キャラレール)。現行 UI の直接の元
- `TW Toolkit Redesign.dc.html` — 方向性の探索。有効なのは **12a(装備のドリルダウン、最新)**、**3a(角丸・アイコン規格)**、**2a(コンポーネント規格)**、**5b(X の上限ロス)**、**5c(防御側パネル)**

骨格(タブ・レール・ホームの到達一覧・計算の 3 段構造)は実装済みなので、この goal は**中身の密度と規格化**を対象にする。モックの仮データ(架空のアイテム名・効果値)は転記しない。

## 段階(それぞれ 1 commit 単位。上から着手する)

### 段階 1 — A 攻撃力の可視化(最大の欠落・backend 拡張あり)**[完了 2026-08-25]**

12a は補正源リストの下に「いまの攻撃力」を常設し、**どの補正源をいじってもこの数字が動く**ことを画面の軸にしている。現状の「いまの実力」シートは最終能力値どまりで A が出ない。

A は依存種別(突き / 斬り / 魔攻 / 魔防 / 複合)で装備係数が変わるので、キャラに **主軸スキル**を持たせて決める(決定 #1)。

- **主軸スキル**をキャラのデータに追加する。domain の `Character` にフィールド、storage に列、`RegisterPane.svelte` の登録フォームに選択欄、`SourcePane.svelte` の「キャラステータス」ペインで変更可
  - 選択肢は `listSkills(game_character_id)`。スキル未収録のキャラがあるので **未選択(null)を許す**。未選択のときは A を出さず「主軸スキルを選ぶと攻撃力が出ます」と書く(空欄にしない)
- `StatPreview`(`crates/domain/src/stat_sources.rs:660`)に **A 攻撃力とその内訳**(ステ攻撃力 / 装備基本 / 装備強化 / 強化倍率)を追加する。算出は `damage.rs:247` の `equipment_attack_power` → `attack_power` と**同じ経路を共有**し、計算を二重に書かない
- `preview_effective_stats`(`commands.rs:128`)に主軸スキル id を渡し、その依存種別で係数を引く
- テシスコアは地域依存(`enhanced_totals(region)`)。キャラ画面はコンテンツ非選択なので **region なしの値**であることを画面に明記する
- `Workspace.svelte` の「いまの実力」に **A 攻撃力 + 内訳**を追加。12a の「いまの攻撃力」フッタは補正源リストの直下に置き、主軸スキル名を添える
- 部位詳細(`SourcePane.svelte` の equipment)に **「この枠の寄与 — 外すと攻撃力がこれだけ減ります」**を出す(その部位を neutral にした A との差分)

段階 1 は **DB migration を含むので Complex 扱い**(CLAUDE.md 実行ワークフロー)。列追加は `character_repository.rs:135` 付近の既存方式に合わせる — `PRAGMA user_version` だけで判定せず**列の実在を確認してから `ALTER TABLE`**(このリポの DB は列を持ちながら `user_version` が 0 のままになりうる)。既存キャラは主軸スキル未選択で読める(`NULL` 既定)。

受け入れ条件: 補正源をどれか触ると A が即時に動く / 主軸スキルを変えると依存種別に応じて A が変わる / 部位を未装備にした差分が寄与値と一致する / 既存 DB を開いても落ちず既存キャラが未選択で表示される / `cargo test --workspace` 通過

結果: すべて満たした(決定記録 docs/claude/decisions.md「2026-08-25 キャラ画面の攻撃力(A)可視化」、実機 docs/screenshots/72〜74)。実装は当初案から 2 点変えた:

- 主軸スキルは domain ではなく **storage の `NewCharacter`/`RegisteredCharacter`** に持たせた(domain に `Character` 型は無く、キャラのデータモデルは storage 側にあるため)。列追加は v5(`main_skill_id TEXT`)
- 部位の寄与は「装備値の差」ではなく **その部位を外した状態を丸ごと計算し直した A との差**にした(シエナのオーラのステ加算が最終能力値経由で A に効くため)

### 段階 2 — 装備ペインの密度(12a との差)**[完了 2026-08-25]**

- **アビリティを Select 4 行に畳む**。現状は 28 件(`equipment_catalog.rs`)の全チェックボックスで、同系統(尖った刃 / 鋭い刃 / 知力 / 耐魔力)の重複チェックも通ってしまう。系統ごとに 1 つ選ぶ形にして排他を構造で保証する
- **エンチャントに上限ゲージ**。12a は行ごとに `150 / 150` + `MAX`。`StatInput` に MAX はあるが上限が `format` の文字列でしか見えない
- **基本とエンチャントを同じ行に並べる**(12a: 左=基本(装備品ごとに固定)/ 右=エンチャント)。いまは別カードなので読み替えが要る
- **装備の合計を表にする**。12a は 基本/強化 × 突き/斬り の表 + 「強化のうち テシスコア・シエナは別の補正源から」注記。現状 `Workspace.svelte` の `.eq-summary` は span 5 つの羅列
- **部位一覧の行にアビリティ数**を出す(12a: アイテム名・強化リボン・アビリティ数・突/斬)
- **補正源の並びを 12a の指定順に**する: キャラステータス / 装備 / シエナのオーラ / テシスコア / 神鳥の聖物 / クラウン / スキル / モンスターカード / ペット。現状(`Workspace.svelte:139`)は ペット・ルーンが上に来ている
- 補正源ヘッダに **「未設定 N 件」**(`NEUTRAL` 判定は既にあるので数えるだけ)
- **PW / SW は既定 ON の固定値にする**(決定 #2)。12a は「スキル」枠へ移すとしていたが移動はしない。パワーウェポン ON・ストロングウェポン Lv6(合計 +20%)を初期値にして表示は 1 行に畳み、**変更は例外操作**として `details` の中へ入れる(ux-guidelines「入力欄は自動値を上書きする例外操作」)。既定値の変更は**新規登録キャラにだけ**効かせ、保存済みキャラの値は書き換えない

受け入れ条件: 同系統アビリティの重複が UI 上で起きない / 上限に達した行が見て分かる / 並びが 12a と一致

結果: すべて満たした(実機 docs/screenshots/75〜78)。追加でやったこと:

- アビリティの系統を **`EquipmentAbilityFamily` としてデータに持たせた**(id 接頭辞や values からの推測にしない)。storage の `validate_equipment_catalog` も同系統の重複を弾くので、UI だけでなく保存でも保証される。旧データの重複は部位詳細を開いたときに 1 つへ畳む
- `Select` の不具合を直した: 選択肢側が空値(「なし」「未装着」)を持つとき、disabled な placeholder と二重になり「なし」を選んでも「選択してください」と表示されていた(ペット・テシスコアのペインにも同じ問題があった)

## 決定(ユーザー 2026-08-24)

1. **キャラ画面の A はキャラの「主軸スキル」の依存種別で出す**。キャラ作成時に選択させ、あとから変更可にする。→ 段階 1 に主軸スキルの追加を含める
2. **PW / SW は固定でよい**。値は人によって変わるが、取っていないユーザーはほぼいない。→ 既定 ON(PW +2% / SW Lv6 = 合計 +20%)にして表示を畳み、変更は例外操作。補正源の移動はしない
3. **角丸は v4 系列(12 / 9 / 6 / pill)で 4 段階に固定**(Claude 判断)。規格シート 3a の 16px 系列は「親しみを増す」ための探索で v4 が採らなかった方向であり、`app.css` 冒頭が v4 準拠と宣言している現状を尊重する。切替ではないので `decisions.md` にはトークン化の事実だけ記録する
