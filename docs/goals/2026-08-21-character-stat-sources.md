# Goal: キャラクターステータスの補正源を厚くする(ペット・ルーン・クラウン・聖物・バフ)

状態: **完了(2026-08-21)**

## 目的

ダメージ計算に使う「実効ステータス」を、素ステだけでなく実際のキャラが持つ恒常補正(ペット S スキル・ルーンスキル・クラウン・神鳥の聖物)と常用バフから自動で組み立てる。ユーザー入力は「段階・Lv・ランクを選ぶ」だけにする(CLAUDE.md UX 方針)。

**必ず先に読むこと**: CLAUDE.md、docs/architecture.md、docs/damage-formula.md §1・§2、docs/decisions.md。

## 前提(ユーザー確認済み 2026-08-21)

- **素ステ(振り分け分)の上限は各 310**(wiki に明記なし。310 はレベル上限でもある)。最終能力値上限 1500(エタの意志で段階的に 2400 まで。既存 docs の「2000」は要修正)
- **キャラステータス(7 種)と装備値(突き/斬り/魔攻/物防/魔防/命中/回避/敏捷/クリ)は計算上別系統**。本 goal はキャラステ側のみ。装備値側(称号・装備アビリティ・シエナのオーラ武器/盾スロット)は別 goal
- ペット/ルーン/クラウン/聖物の加算はすべて素ステ 310 の外側(最終能力値側)

## 到達点(受け入れ条件)

1. `cargo test --workspace` が通る
2. キャラ登録画面で、素ステ(上限 310)に加えて ペット S スキル / ルーン Lv / クラウン / 聖物段階 / 常用バフ / 調整値 を選択式で登録でき、再起動後も残る
3. ダメージ計算が登録内容から `StatModifierSet` を自動構築し、ステトレースに各補正源の寄与が内訳として出る
4. 同名枠の排他(①/②/退魔師の恵み枠/祝福のポーション枠)が UI と domain の両方で守られる
5. 決定事項・出典が docs/decisions.md と gamedata に記録される。docs/damage-formula.md のエタ上限を 2400 に修正

## スコープ

### 含む

- **domain**: `StatSources`(pet_skills / rune_levels / crown / sacred_relic / buffs / adjustments)と `StatSources → StatModifierSet` の純関数、寄与内訳トレース。`BaseStats` の 310 バリデーション
- **gamedata**: ペット段階表、ルーン 7 スキル、聖物段階、バフカタログ(名称・対象・値・レイヤー・重複枠)。出典 URL と取得日を持たせる
- **storage**: `character_stat_sources`(キャラ 1:1、JSON 列でよい。スキーマは storage 内で閉じる)
- **UI**: 登録画面にセクション追加。数値入力は 改・信頼 / 固定増加系 / クラウン / キャラスキル% / 調整値のみ

### 含まない

- 装備値側(称号・装備アビリティ・シエナのオーラ)
- モンスターカード(構造は固定値層で単純だが、カード 449 行のカタログ化は別 goal)
- デバフ(敵からの倍率B マイナス)
- 属性値(ルーン属性・カード属性)

## 確定事項(ユーザー回答)

- 「週五社のためのポーション」= 守護者のためのポーション(+10%)
- アンリーシュは +20% 固定(ON/OFF)
- クラウンはステごとの数値入力(0〜300)
