# Goal: 最小 end-to-end — キャラ登録からダメージ計算まで

## 目的

TalesWeaver Toolkit の最初の動くスライスを作る。キャラクターを登録し、スキルと敵を選ぶとダメージ計算結果(トレース付き)が表示されるデスクトップアプリ。

**必ず先に読むこと**: CLAUDE.md、docs/architecture.md、docs/damage-formula.md。
矛盾を見つけたら黙って進めず報告する。優先順位: **ゲーム仕様の正は talewiki**(その整理が damage-formula.md)> アーキテクチャ・進め方は docs > 本プロンプト。ただし矛盾の内容によるので、機械的に上書きせず判断理由を docs/decisions.md に残す。

## 到達点(受け入れ条件)

すべて満たしたら完了:

1. `cargo test` が workspace 全体で通る
2. Tauri アプリが起動し、次の一連の操作が GUI で完了する:
   - キャラクターを登録する(名前・キャラ選択・素ステ6種・覚醒段階・エタLv)→ SQLite に保存され、再起動後も残る
   - 登録キャラを選び、スキルと敵を選ぶ → ダメージ計算結果(最小・最大・クリティカル時)が表示される
   - 計算の全中間値(カテゴリごとの集計値と式の各段)がトレースとして展開表示できる
3. スクリーンショット3枚(①キャラ登録、②計算結果、③トレース展開)で一連の操作を実証する
4. CLAUDE.md にビルド・実行・テストのコマンドを追記し、「現状」節を更新する
5. 仮決定した事項がすべて docs/decisions.md に記録されている

## スコープ

### 含む

- Cargo workspace の足場: `crates/domain`, `crates/gamedata`, `crates/storage`, `apps/desktop`(docs/architecture.md の構成。`tools/scraper` は今回作らない)
- **domain**: docs/damage-formula.md の4段パイプライン(能力値計算 → カテゴリ集計 → 与ダメージ式 → 段数・追加ダメージ)
  - **カテゴリの器(enum・種別・キャップ・加算集計・トレース)は約30カテゴリ全部を定義**し、未使用カテゴリは中立値(割合=1.0、固定値=0)で式に参加させる
  - 実際に値を入れて単体テストで検証するのは主要カテゴリのみ: A(攻撃力)、B(乱数)、C(敵防御)、D(スキル倍率)、F(Cri倍率)、G(クリダメ増加)、H(コンボ)、I(属性差)、N(覚醒)
  - J(カット率(プレイヤー))は**器のみ**。プレイヤー被ダメ側のカテゴリであり、与ダメージ(対モンスター)が主目的の本ツールではスコープ外
  - 丸めは専用関数(`[]`=floor、`{}`=小数2位切捨、バフごと floor)として実装し、式には裸の丸めを書かない
- **gamedata**: 最小シードを手書きで用意(キャラ1体分の係数、スキル3〜5件、敵3体程度)。値は docs/damage-formula.md と旧リポの数値を参考にしてよいが、出典をデータ内に記録する
- **storage**: rusqlite。登録キャラの CRUD のみ
- **UI**(Svelte + TypeScript): 情報密度の高いダークテーマで整える。画面は2つ:
  - キャラ登録・一覧
  - ダメージ計算(キャラ・スキル・敵のセレクタ + 結果 + トレース展開)
  - 数値の手入力欄は作らない。すべて選択式(CLAUDE.md「UX の基本方針」)

### 含まない(やらない)

- 強化提案・ロードマップ・やりたいこと索引・実測突き合わせ機能
- talewiki スクレイパー、旧リポ JSON の一括取込
- バフセット UI(カテゴリ集計の器はあるが、UI からのバフ選択は次回)
- Web/モバイル対応、i18n、自動アップデート

## 進め方の制約

- CLAUDE.md の実行ワークフロー(researcher / implementer / reviewer への委譲)に従う
- コミットは意味のある単位で刻む(足場 / domain / storage / UI / 統合)
- 未確定の仕様(wiki 未取込の式など)に当たったら、**止まらずに仮決定して docs/decisions.md に「決定・理由・確認方法」を1行ずつ記録**して進む
- 型名・関数名はドメイン語彙。カテゴリ記号(A〜Y)は doc コメントの出典情報としてのみ使う(CLAUDE.md「アーキテクチャ方針」)
- ライブラリ選定は「実績あるものを使う」原則に従い、選定理由を docs/decisions.md に記録
