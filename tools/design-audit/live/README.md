# 実機監査スクリプト(design-system の B 監査)

`run.py`(機械監査)がソースを読むのに対して、ここは**動いているアプリを測る**。
規格のうち「座標が動かない」「同時に動く」「寸法が段に収まっている」は、
ソースを読んでも分からないので実機で測る。

## 走らせ方

`gui-smoke` skill の手順でアプリを起動してから(CDP が 9222 で開いた状態):

```
NODE_PATH=/c/github/private/twtoolkit/node_modules node tools/design-audit/live/<name>.js
```

## 何を測るか

| ファイル | 観点 |
|---|---|
| `round4.js` | §09 規則 1(押した要素が動かない)/ 規則 3(重なるものがレイアウトを押さない)/ §07(「適用」ボタンが無い) |
| `round5.js` | §00(未収録を 0 や空白で埋めていない)/ §03(斜線の用途)/ §05(数値書体)/ §06(アイコン単独表示) |
| `round6.js` | 全画面(計算 4 状態・補正源 17 ペイン・レール折りたたみ・ホーム)で §04 角丸・§05 書体・§06 アイコン・§10 0.5s 超 |
| `round9.js` | §02 帯の高さ・§05 実寸スケール・§01 面の 3 層 |
| `row.js` | §09 規則 1 を補正源の行で(**完全に見えている行**で測る) |
| `digits.js` | §09 規則 4(桁が増えても隣が動かない)。値を実際に変えて座標を比べる |
| `sim10.js` | §10 規則 2(同時に変わるものが全部動く)。跳ねたクラスを MutationObserver で拾う |
| `round11.js` | 登録ペイン(新規キャラ)とエラー帯の重なり |
| `surfaces.js` | §01「白 = 編集できる面 / インセット = 読み取り専用」を全画面で。**枠を持つ箱**の背景を実際の色で見る |
| `sweep.js` | §09 規則 1・3 を**押せる要素の自動列挙**で(全タブ・全ペイン、1,200 個超)。手書きのリストだと漏れる |

## 測るときの注意

- **見切れている行を押すと、ブラウザがフォーカスを視界に入れるためにスクロールする。**
  それは §09 規則 1 の違反ではないので、完全に見えている要素で測る(`row.js` がその形)
- **値が上限に張り付いていると、操作しても数字が動かない**ので §10 の検証にならない。
  上限に当たっていない値(調整の加算など)で測る
- **ビューポート座標で測らない。** Playwright の `click()` は要素を視界に入れるためにスクロールするので、
  アプリが動いていなくても座標が変わる。`offsetLeft` / `offsetTop`(レイアウト上の位置)で測り、
  押すときも `dispatchEvent("click")` にする(`clickall.js` がその形)
- **前の測定で開いたペイン・スクロールが残っていると座標が動いて見える。** 1 件ごとにリロードする
- **§01 の「箱」は枠を持つ面のこと。**点線の区切り・カード(内容の器)・裸のテキストは箱ではない。
  そこを分けないと候補が数百件出て使い物にならない(`surfaces.js` の判定がその形)
- **保存・削除・登録のボタンを押さない。** 監査が開発 DB を書き換えると、あとで
  「実装のバグ」と区別が付かなくなる(`sweep.js` の `DESTRUCTIVE` で弾いている)
- スクリプトはアプリの状態(localStorage・DB)を変えることがある。検証後は元に戻す
